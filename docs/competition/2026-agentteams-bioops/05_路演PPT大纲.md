## 建议叙事节奏

1. **先讲复杂任务，而非先讲模型。** 让评委理解为何需要角色、审批和证据。
2. **再讲协同闭环。** 把 AgentTeams 能力清楚映射到 Case、Work Item、Role、审批和状态。
3. **然后讲工程可信性。** 用 Skill 契约、Artifact、质量门、幂等、审计和回滚证明不是 Demo。
4. **最后讲落地与复用。** 一套 Team/Skill/Bridge 模式如何复制到不同组学任务与行业客户。

## 现场答辩高频问题与建议回答

| 问题 | 回答要点 |
| --- | --- |
| 为什么不是一个通用 Agent 就够？ | 该场景需要权限隔离、质量独立性和可审计责任链；多角色不是为了“多说话”，而是为了防止同一 Agent 自己申请、执行、验收。 |
| AgentTeams 在方案中具体做了什么？ | Team/Role 定义身份，Case 承载项目，Work Item 承载可领取工作，审批网关控制高风险动作，事件和房间/进度承载状态追踪。 |
| 结果正确性靠模型吗？ | 不靠。模型只做任务拆解、解释和结构化追问；流程输出、Artifact 校验、QC 指标与版本化规则共同决定质量门。 |
| 如何避免重复提交和失控重试？ | 提交使用幂等键；事件使用 dedupe key；重试有分类和预算上限；高风险动作必须审批。 |
| RAG 是否真的有必要？ | 不是把文档塞给模型，而是让 SOP、质量规则、交付规范和历史复盘以带版本、带来源的证据参与决策；证据不足则转人工。 |
| 当前完成度如何？ | 已有 MAS、Bridge、角色/Skill 契约、Case/Work Item、审批和证据基础；真实 Worker 和 Matrix 部分按默认关闭/待部署验收口径说明，比赛重点是打通并展示完整可验证闭环。 |
