## 1. 摘要

CygnusX BioOps 解决的是生命科学研发中"组学数据分析交付"这一高频、高价值、长链路任务的工业化问题。平台把专家搭建并审核的标准分析流程框架化为网页操作与任务提交，以"**领域 Agent + 沉淀 Skill 的联动体**"驱动从需求理解到受控执行的全过程，并对每一次分析留下版本化流程定义、运行环境快照与机器可校验的证据链。

**一句话定位：** 别的 AI 工作台让 AI 写流程、信结果；本平台让 AI 调度经过专家审核、带版本与环境快照的流程——每一次调用有权限、每一个产物可追溯、每一个结论有证据。

**量化价值（测量口径：仅指人工操作与沟通时间，不含计算运行时间）：**

| 场景 | 传统方式 | 本平台 | 降幅 |
| --- | --- | --- | --- |
| 提交一次标准分析（如 bulk RNA-seq 差异分析） | 手动整理 config/样本表/分组表、命令行提交，约 20 min | 网页表单 + 任务提交，约 5 min | ~75% |
| 基于结果的增量分析需求（已沉淀 Skill 覆盖范围内） | 专业人员解析问题、设计方案，约 1 天 | 领域 Agent 调用平台沉淀的 Skill 完成方案与提交，约 30 min，运行信息与环境全程记录 | ~90% |
| 定制化流程改造（如 mapping 从 STAR 切换为 HISAT2） | 专业代码编写 + 审核整条流程，约 5 天 | 替换/新增一个流程模块并继承平台质量门与交付链路，约 1 天 | ~80% |
| 人员更替后的项目复现与交接 | 从聊天记录和散落脚本中"考古"，以周计且常失败 | 项目级上下文文档 + 交付 README + md5 校验清单 + 版本化流程 YAML，接手即可复现 | 从"不可复现"到"可复现" |

## 2. 行业痛点

药物研发、种业育种、医学检验与科研服务企业的组学分析交付，普遍存在五类结构性问题：

1. **入口分散、提交繁琐。** 一次标准分析要在聊天工具、表格、脚本、任务系统之间往返：整理 config.yaml、samples.csv、contrasts.csv，再手动提交。操作入口多、表单靠手工、错误到计算后期才暴露。
2. **增量需求依赖专家。** 分析结果出来后用户的新问题（换一组对比、补一个富集分析）需要专业人员重新解析需求、设计方案，排队以天计。
3. **定制化成本高。** 换一个比对器、加一步质控，都意味着专业人员改写整条流程并走代码审核，周期以周计。
4. **AI 产物不可信。** 现阶段大量 AI 工作台完全信任 AI 生成的流程与分析结果，既无法复现也无法追溯，在药企、医检等强合规场景不可交付。
5. **组织知识随人流失。** 生信项目时间跨度大、涉及人员多；分析人员离职后，其代码与交接文档难以复现，问题排查近乎考古。

痛点 1–3 是**效率问题**，痛点 4 是**可信问题**，痛点 5 是**组织延续性问题**。现有工具各自解决其中一环，没有一个系统把三者放进同一个闭环。

## 3. 解决方案

平台的核心机制是 **Agent × Skill 联动体**：领域 Agent 负责理解需求、拆解任务、解释结果；Skill 是带输入输出契约、失败语义和权限边界的稳定业务动作；流程是专家审核、版本化管理的资产。三者通过声明式配置（`data/ai/*.yaml`、流程 YAML、Skill 市集元数据）装配，而非临时提示词拼装。

### 3.1 标准流程框架化：从手动运行到网页提交

平台将专家搭建并审核的分析流程沉淀为声明式、版本化的流程定义（如 `flows/rna_seq.yaml` v2.3.0），通过参数白名单（`allowed_parameters`）、前端表单、资源画像与任务队列，把"整理表单 + 命令行提交"收敛为一次网页操作。

- 输入缺失（样本表、分组、参考基因组版本）在预检阶段即被阻断，而不是计算数小时后失败。
- 提交动作携带幂等键，重试与网络抖动不会造成重复计算。

**效果：一次标准分析的提交从约 20 min 降到约 5 min。**

### 3.2 Skill 沉淀：增量需求从"排期等专家"到"即时响应"

平台把稳定业务动作沉淀为 Skill（内置可执行 Skill 市集现有 38 个），配合知识库 RAG（pgvector + 混合检索）中的领域 SOP 与规范。当用户基于分析结果提出新需求时，领域 Agent 直接在已沉淀 Skill 的覆盖范围内完成"问题解析 → 方案设计 → 任务提交"，无需专业人员介入。

**效果：已覆盖领域的增量需求从约 1 天降到约 30 min；且每次运行的参数、环境、产物引用全程记录，自动进入证据链。**

### 3.3 模块化定制：从"重写整条流程"到"替换一个模块"

流程被拆解为模块（rule）：比对、定量、质控、统计、报告各自独立、带版本。定制化改造（如 STAR → HISAT2）的工作单元从"编写并审核整条流程"缩小为"替换/新增一个流程模块"，并自动继承平台的质量门、证据与交付链路。

> 现状说明（诚实口径）：当前内置 RNA-seq 流程的比对器尚未开放为表单参数，切换比对器仍需新增流程变体或模块；本平台的价值在于这一改动被收敛在声明式配置与模块替换上，而非整链重写。

**效果：典型定制从约 5 天降到约 1 天。**

### 3.4 可信交付：专家审核流程 + 版本控制 + 环境快照

这是与"纯 AI 工作台"的根本差异：

- **流程不由 AI 生成。** 内置流程由领域专家搭建与审核，版本化管理；Agent 负责拆解需求、调度流程、解释结果，不拥有 shell、流程 YAML 写权限或数据库权限。
- **质量不由模型"感觉"判断。** 质量门基于结构化 QC 规则（如 mapping_rate ≥ 0.70、Q30 ≥ 0.80）与 Artifact 完整性校验；规则缺失时强制转人工复核。
- **每一步可追溯。** 关键调用与状态变化产生证据事件，绑定 trace、规则版本、Artifact 引用与决策原因；高风险动作需人工审批确认后才执行。

### 3.5 组织知识延续：人员更替不影响项目复现

针对"项目跨度大、人员流动后交接困难"的行业痛点，平台把每个项目的知识沉淀为结构化资产：

- **项目强制归属：** 创建 AI 助手 / AI 工作台会话必须绑定项目（项目含 ID、名称、描述、客户字段），在用户目录下形成 `projects/{slug}/` 项目文件夹；"项目管理"页可按项目查看全部历史会话与历次分析（已实现）。
- **项目级上下文文档（AGENTS.md）：** 项目在首次分析归档时自动生成 `AGENTS.md`（项目名、客户、描述、创建时间），此后每次分析完成自动追加一条分析记录（时间、运行目录、分析类型、状态、摘要），形成项目级可追溯台账；该文档同时注入 Agent 工作区作为项目记忆（已实现，平台代码生成而非提示词约定）。
- **每次分析的时间戳归档与 README：** 每次分析按 `projects/{slug}/runs/{分析名}-{时间戳}/` 归档，由平台代码强制生成 `README.md`，含项目名称、客户、时间戳、分析类型与流程版本、最终结果清单（文件大小 + MD5）、代码/脚本清单、软件与版本、分析环境（已实现）。
- **机器可校验的环境快照与完整性证明：** 每次运行同步生成结构化 `environment.json`（运行时镜像及其软件清单、流程 YAML 版本、平台版本/git sha、Python 版本、资源画像）；交付物可用内置校验工具逐文件核验（SUCCESS/MISSING/FAIL 三态），输出 `verification.tsv`（已实现）。
- **版本化流程 YAML + Artifact Registry：** 流程定义、参数、规则版本与产物校验摘要一并归档，构成"可追溯 YAML + md5 check"的证据组合。

**效果：交接从"靠口述"变成"靠证据"；接手者可以复现分析、定位问题，而不是重建环境猜参数。**

## 5. 竞争格局与差异化

| 维度 | 通用 AI 工作台 / Agent 平台 | 传统生信流程平台 | CygnusX BioOps |
| --- | --- | --- | --- |
| 流程来源 | AI 即时生成，未经审核 | 专家固化，不可扩展 | 专家审核 + 版本化，AI 只调度不生成 |
| 结果可信性 | 无法复现、无法追溯 | 依赖个人习惯，证据不完整 | 证据链 + 环境快照 + md5 校验，机器可核验 |
| 定制成本 | 低但不可控 | 高（重写流程） | 模块替换，继承质量门与交付链 |
| 人员更替 | 知识在对话里，随人走 | 知识在个人脚本里，随人走 | 知识在 AGENTS.md/README/版本化 YAML 里，留下 |
| 权限与合规 | Agent 权限宽泛 | 共享高权限入口 | 能力边界声明 + 审批确认 + 幂等 + 审计 |

核心壁垒不是某个单点功能，而是三者的组合：**专家审核的流程资产 × Agent×Skill 联动机制 × 机器可校验的证据体系**。纯 AI 平台补不了流程资产与合规机制，传统流程平台补不了 Agent 调度与证据体系。

## 6. 产品演进重点与增长飞轮

### 6.1 现阶段重点：打磨 Agent × Skill 联动体

当前阶段的产品重心不是扩张协同形态，而是把主线做深：

- **Skill 覆盖度与质量：** 扩充领域 Skill 的数量与场景覆盖，完善版本治理与失败语义，让"增量需求 30 min 响应"覆盖更多分析类型。
- **Agent 调度准确性：** 优化领域 Agent 对需求的解析、Skill 选择与参数填充的准确率，降低人工纠偏率。
- **证据链自动化：** 项目级 AGENTS.md 台账、run 级 README 与 `environment.json` 已由平台代码强制生成；下一步补齐普通聊天会话的扫尾归档与证据项独立文件导出，让"交接靠证据"零额外操作。
- **流程参数化：** 将比对器等高频定制点开放为表单参数或流程变体，让"5 天 → 1 天"进一步向"1 天 → 1 小时"演进。

### 6.2 增长飞轮（路线图）：分析 rule 的复利积累

平台的长期增长逻辑是**分析 rule（模块）的复利积累**：

```text
定制需求 → 沉淀为新 rule（流程模块，专家审核后入库）
        → rule 复用率上升，后续同类定制成本继续下降
        → 运行数据（成功率、质量指标、失败原因）回流为规则与 Skill 的改进依据
        → 定制 → 稳定运行 → 高复用 的正循环
```

- **已实现的基础：** Skill 市集（版本元数据 + 可安装目录）、版本化流程 YAML、运行证据与质量决策的结构化记录，使 rule 的沉淀与复用具备载体。
- **路线图（非现有能力）：** 由 Snakemake Agent 承担流程模块的组装、依赖校验与升降级治理，结合上述数据飞轮，实现"从定制到稳定运行"的高效与高准确运转。

## 7. 目标市场与可复制性

| 目标用户 | 典型任务 | 主要收益 |
| --- | --- | --- |
| 药企转化医学/生信平台 | 临床队列 bulk RNA-seq 差异分析与报告交付 | 降低样本配置错误与结果追溯成本 |
| 种业与农业科研团队 | 多批次转录组项目的质控、分析、可视化 | 统一流程版本、参考基因组与证据标准 |
| 医学检验/科研服务机构 | 面向客户的标准化分析交付 | 标准化交付物 + 完整证据链，客户可核验 |
| 高校核心设施 | 多课题组并行提交的测序分析需求 | 以表单、队列与质量门控制服务边界 |

可复制的不是某一个 RNA-seq 流程，而是"**受控任务交付**"模式：替换预检字段、允许的流程、Artifact 类型、质量规则与交付模板后，可迁移到 ATAC-seq、单细胞、多组学，乃至药物筛选、临床报告审核等非生信的企业分析任务。

商业化路径：**私有化部署 License ＋ 年度维保 ＋ 行业模板定制服务**。

| 收入项 | 定价 | 说明 |
| --- | --- | --- |
| 私有化部署 License | 单套 15–50 万元 | 按部署节点与功能模块分档；面向药企研发部门、医学检验机构、高校与科研平台 |
| 年度维保 | License 额的 15–20%/年 | 版本升级、质量规则更新与运维支持，形成持续现金流 |
| 模板定制与流程接入服务 | 单项目 3–10 万元 | 行业模板定制、流程接入与培训 |

私有化部署、数据不出域的产品形态，正好承接药企、医检等强合规机构"组学分析依赖外包、过程不透明、数据需出域"的替代预算；单机构组学分析外包年支出普遍在数十万元级，替代与承接空间明确。

**客户侧 ROI（测算口径，以试点数据持续校准）：** 预检自动阻断缺失信息，避免无效计算，单项目交付周期预计缩短 30–50%，重跑率与无效算力成本显著下降；完整的交付证据链可降低客户合规审计成本。

## 12. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 量化工时数字被质疑 | 所有数字标注测量口径（人工操作时间，不含计算运行）；以 staging 实测数据持续校准 |
| 定制能力被夸大解读 | 明确定制单元是"模块替换 + 流程变体"，比对器等关键参数尚未全部表单化 |
| AI 不可控风险 | Agent 无 shell/YAML/数据库写权限；质量门规则缺失即转人工；高风险动作需审批确认 |
| 外部依赖不可用 | 工具调用显式超时与错误分类；Redis 不可用时由 PostgreSQL Outbox 重建事件投影；高风险问题切换人工处理 |
| 实验性功能干扰主线认知 | AgentTeams 等实验层默认关闭、独立部署；核心路径不依赖其存在，回滚只需关闭功能开关 |

## 13. 结语

生命科学研发的数据分析正在从"个人手艺"走向"工业交付"。CygnusX BioOps 的答案不是更聪明的 AI，也不是更多的 Agent，而是更可靠的系统：**把专家的流程变成可复用的资产，把 Agent 的能力约束在 Skill 契约与证据的边界内，把项目的知识沉淀为不随人流失的组织财富**——能拆解、能执行、能验证、能审计、能恢复、能积累。
