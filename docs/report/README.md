## 核心结论

### 安全现状：4.75/10，距离万人级公网（8.5/10）差距显著

**三大致命风险**（必须修复才能上线）：
1. 🔴 **沙盒 Docker Socket 逃逸**：当前 `docker.from_env()` 需挂载 docker.sock = 宿主 root，且当前容器化部署未挂载 = 沙盒功能不可用。万人级改 K8s Job per 执行 + gVisor/Kata。
2. 🔴 **JBrowse /tracks 路径越权**：nginx 直接 alias 全用户数据目录，无鉴权，任何人可下载任意组学数据。改 FastAPI 鉴权代理。
3. 🔴 **JWT 无吊销 + Refresh 无轮换**：被盗 token 30 分钟内无法止损。加 Redis 黑名单 + 轮换检测。

### 调度架构：设计优秀但单机实现，需重构分布式

**优点**：BaseExecutor 抽象 + 回调解耦 + 状态机 + 饼干四点集成，设计层面达到生产级。

**瓶颈**：单一 analysis 队列、无优先级、单 Beat、无资源感知、流程路径硬编码宿主。万人级需多队列分层 + HPA + K8s/Slurm 集群执行 + 流程容器化。

### K8s 迁移：最简 5 步，托管服务优先

1. 镜像准备（锁定版本、web 不装 snakemake）
2. Helm Chart 骨架（web/worker/beat/flower + ingress + networkpolicy）
3. 核心 manifests（HPA + NetworkPolicy + PVC）
4. 存储接入（NAS ReadWriteMany + OSS 直传）
5. DB 迁移（推荐云 RDS 托管，不自管有状态）

**成本**：万人级（1000 日活）约 ¥1.25 万/月，人均 ¥1.25/月。

### 存储迁移：三级分层，省 70% 成本

热存储 NAS SSD（原始上传/活跃任务）+ 温存储 NAS 效率型（结果）+ 冷存储 OSS（归档）。StorageBackend 抽象层让应用无感切换，大文件用 OSS 预签名 URL 直传不经后端。

### 节点分离：控制面/数据面/计算面三层物理分离

- **控制面**：Web + Beat + 托管 DB/Redis，轻量弹性
- **数据面**：Worker 按队列分组，HPA 按队列深度自动扩缩
- **计算面**：Snakemake 流程容器化，提交到 Slurm/K8s Job，按任务拉起释放

## 万人级扩展路线图

| 阶段 | 时间 | 目标 | 关键交付 |
|------|------|------|---------|
| **0 紧急** | 1-2 周 | 消除致命安全风险 | 沙盒加固、/tracks 修复、JWT 吊销、备份 |
| **1 控制面** | 2 周 | Web 上 K8s + 托管 DB/Redis | Helm Chart、云 RDS、云 Redis、Ingress+cert-manager |
| **2 数据面** | 2 周 | Worker 分离 + NAS 接入 | Worker 独立 Deployment、NAS PVC、多队列 |
| **3 存储抽象** | 2 周 | StorageBackend + OSS | 抽象接口、OSS Backend、file_records 扩字段、数据迁移 |
| **4 流程容器化** | 3 周 | 每流程打包镜像 | Snakefile 容器化、YAML 声明 container_image、路径修复 |
| **5 集群执行** | 2 周 | K8sJobExecutor 或 Slurm | 执行器实现、registry 注册、端到端验证 |
| **6 弹性优化** | 持续 | HPA + 成本优化 | Prometheus 自定义指标、Worker HPA、抢占式实例 |
| **7 安全加固** | 持续 | 生产级安全 | RBAC+ABAC、KMS、监控告警、Falco、渗透测试 |

**总工期**：约 3-4 个月达到万人级生产可用，后续持续优化。

## 一句话总结

CygnusX 架构设计扎实（DDD + 执行器抽象 + 双栈解耦），但从组内工具到万人平台需跨越**安全加固、K8s 化、存储分层、节点分离、流程容器化**五道坎。优先级：**先修致命安全漏洞 → 控制面上 K8s → 存储抽象 → Worker 分离 → 流程容器化 → 集群执行**。执行器抽象设计良好，业务层改动小，主要工作量在基础设施与流程容器化。
