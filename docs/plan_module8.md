# OmicHub "AI Copilot 与交互式代码执行沙盒"模块 — 执行计划

## 目标
为 OmicHub 设计"AI Copilot 与交互式代码执行沙盒"模块，输出包含技术选型、架构设计、工作流示例、融合方案的报告，并融入现有架构文档。

## Stage 1 — 并行子代理设计（4个子代理同时工作）

| 子代理 | 负责模块 | 输出 |
|--------|----------|------|
| 技术选型分析师 | 1. 技术栈选型与评估 | 前端UI/后端调度/沙盒执行/LLM Agent 的全面对比表格与推荐 |
| 架构设计师 | 2. 模块架构设计图 + 组件设计 | Mermaid架构图（2-3张）、组件接口定义、数据流描述 |
| 工作流设计师 | 3. 工作流闭环示例 | 单核转录组聚类的完整全链路生命周期描述（含时序图） |
| 融合架构师 | 4. 与 OmicHub 主框架融合方案 | 用户系统集成、数据挂载设计、Nextflow/Snakemake调度集成、MCP协议融合 |

## Stage 2 — 整合与审校
- 合并所有子代理输出为完整报告（Markdown）
- 统一术语、交叉引用
- 追加到现有架构文档末尾

## Stage 3 — 文档更新
- 合并到主文档
- 重新转换为 docx 格式

## 约束
- 必须兼容已有技术栈（Vue 3 + FastAPI + PostgreSQL + Redis + Docker）
- 必须支持 MCP 协议
- 必须考虑组内仅1人生信维护的极简运维原则
- 沙盒方案必须私有化部署（不考虑纯云方案如 E2B Cloud，但可参考其架构）
