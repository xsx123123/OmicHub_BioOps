## 一、现状梳理

### 1.1 存储根目录

| 配置来源 | 路径 | 优先级 |
|----------|------|--------|
| `data/CygnusX.yaml` → `storage.data_root` | `/data/cygnusx` | 最高 |
| 环境变量 `STORAGE_PATH` | `/data/cygnusx` | 中 |
| 代码兜底 `_DEFAULT_DATA_ROOT` | `/data/cygnusx` | 最低 |

解析逻辑位于 `src/cygnusx/infrastructure/config/storage_config.py`。

### 1.2 当前目录布局

```
/data/cygnusx/
├── users/{user_id}/
│   ├── raw/                          # 用户上传原始文件（分片合并）
│   │   └── {directory}/             # 用户自建子目录
│   ├── results/{flow_id}/{task_id}/  # 分析流程（RNAFlow/ATACFlow）输出
│   ├── raw_data/{accession}/         # EBI/NCBI/云存储下载产物
│   ├── downloads/                    # 用户打包下载
│   ├── enrichments/{project}/{task_id}/  # 富集分析结果
│   ├── workspace/
│   │   └── chat-uploads/            # AI 聊天附件
│   └── temp/                         # 系统默认临时目录
│
├── blast/
│   ├── db/                           # BLAST 数据库（全局共享）
│   ├── uploads/{user_id}/{task_id}/  # BLAST 查询序列上传
│   └── results/{user_id}/{task_id}/  # BLAST 比对结果
│
├── qc/tasks/{task_id}/              # FASTQ QC 工具（独立根路径）
│   ├── input/
│   ├── output/
│   ├── reports/

│   └── logs/
│
```

### 1.3 各模块文件管理方式对比

| 模块 | 路径构建方式 | DB 记录 | 文件注册 | 下载接口 |
|------|-------------|---------|----------|----------|
| **文件上传** | `FileService.user_raw_dir()` | `file_records` 表 | 有（完整元数据） | `GET /files/{id}/download` |
| **分析流程** | `TaskService._make_work_dir()` | `tasks` 表 (work_dir, result_path) | 无（仅报告注册） | `GET /reports/{id}/files/{fid}/download` |
| **BLAST** | `BlastService._result_dir()` | `blast_tasks` 表 (result_path) | 无 | `GET /tools/blast/tasks/{id}/download` |
| **富集分析** | `EnrichmentService._work_dir()` | `tasks` 表 (result_data JSON) | 无 | `GET /tools/enrichments/tasks/{id}/download` |
| **FASTQ QC** | `tool_configs/fastq_qc/config.yaml` | 独立任务表 | 无 | 独立接口 |
| **数据下载** | `DownloadService._make_work_dir()` | `download_tasks` 表 | 完成后注册为 `file_records` | `GET /files/{id}/download` |
| **AI 聊天附件** | `get_user_chat_upload_dir()` | 无 | 无 | `GET /files/chat-upload/{uid}/{filename}` |
| **报告** | `ReportService` | `reports` + `report_files` 表 | 有 | `GET /reports/{id}/files/{fid}/download` |

```
    ├── delivery_manifest.json
    ├── report_data/project_summary.json
    └── Analysis_Report/index.html
```

## 二、问题诊断

### 2.1 路径约定不统一（核心问题）

| 问题 | 具体表现 |
|------|----------|
| **用户数据分散** | 同一用户的数据分布在 `users/{uid}/`、`blast/uploads/{uid}/`、`qc/tasks/` 三个独立树 |
| **路径构建分散** | 每个 Service 各自拼路径（`_make_work_dir`、`_work_dir`、`_result_dir`），无统一工厂 |
| **配置源碎片化** | `settings.storage_path`、`settings.blast_db_root`、`settings.enrichment_data_mount`、`tool_configs/fastq_qc/config.yaml` 各自定义根路径 |
| **命名不一致** | 上传目录: `raw/` vs `blast/uploads/`；结果目录: `results/` vs `blast/results/` vs `qc/tasks/` |

### 2.2 文件注册不完整

- 分析流程的中间产物和最终结果**不注册**到 `file_records`，只有生成报告时才创建 `report_files` 记录
- BLAST / 富集分析结果仅存于各自任务表的 `result_path` 字段，文件管理器看不到
- AI 聊天附件完全无 DB 记录
- 用户无法在一个统一视图中看到"我的所有文件"

### 2.3 文件访问接口碎片化

当前至少 5 套独立的文件下载路径：
1. `GET /api/v1/files/{id}/download` — 通用文件
2. `GET /api/v1/reports/{id}/files/{fid}/download` — 报告附件
3. `GET /api/v1/tools/blast/tasks/{id}/download` — BLAST 结果
4. `GET /api/v1/tools/enrichments/tasks/{id}/download` — 富集结果
5. `GET /api/v1/files/chat-upload/{uid}/{filename}` — 聊天附件

前端需要针对不同来源调用不同 API，无法统一处理"打开/下载/分享一个文件"。

### 2.4 配额与生命周期管理盲区

- 配额统计依赖 `du -s` 扫描 `users/{uid}/` 目录，但 BLAST、QC 等目录不在此树下 → **配额漏算**
- 清理任务只处理 `file_records` 中注册的文件和 `.tmp/` 临时区 → 未注册的工具结果**永不清理**
- `data_deliver/` 目录有时在 `work_dir` 内，有时在 `work_dir_parent` → 归档逻辑可能遗漏

### 2.5 跨模块文件引用缺乏标准协议

- `ManagedFileResolver` 支持 `upload://`、`file://`、`directory://`、`sample_sheet_ref://` 四种 URI
- 但 BLAST 结果、富集结果、流程中间产物无法通过这些 URI 引用
- AI 工具链无法统一访问"上一步分析的结果文件"

## 三、统一目录规范设计

### 3.1 设计原则

1. **用户数据单一根**: 所有用户产生的数据必须在 `users/{user_id}/` 下，便于配额、清理、迁移
2. **按职能分区**: 输入(input) / 输出(output) / 临时(temp) 清晰分离
3. **工具无关性**: 目录结构不因工具名而异，统一用 `tasks/{task_id}/` 承载
4. **全局共享独立**: 数据库、参考基因组等共享资源放在 `shared/` 下，不混入用户树
5. **向后兼容**: 旧路径通过软链接或 DB 记录的 `legacy_path` 字段兼容

### 3.2 目标目录结构

```
/data/cygnusx/                          # storage.data_root
│
├── users/{user_id}/                    # ===== 用户数据区（配额管辖）=====
│   │
│   ├── inbox/                          # 上传入口（原 raw/）
│   │   ├── {file_id}_{original_name}  # 去重后的文件（保留原始名做 display_name）
│   │   └── {user_dir}/               # 用户自建目录（文件管理器）
│   │
│   ├── tasks/                          # 所有计算任务的统一工作区
│   │   └── {task_id}/                 # 一个任务一个目录（UUID）
│   │       ├── meta.json              # 任务元数据快照（工具类型、参数、创建时间）
│   │       ├── input/                 # 任务输入（软链接到 inbox/ 或复制）
│   │       ├── output/                # 任务输出（最终结果）
│   │       ├── work/                  # 中间产物（可清理）
│   │       └── logs/                  # 任务日志
│   │
│   ├── projects/                       # 用户项目（组织多个任务）
│   │   └── {project_slug}/
│   │       ├── project.json           # 项目元数据
│   │       └── tasks -> [task_id...]  # 关联的任务列表
│   │
│   ├── downloads/                      # 打包下载暂存
│   │
│   └── workspace/                      # AI 工作区
│       ├── chat-uploads/              # 聊天附件
│       └── sandbox/                   # 沙箱执行产物
│
├── shared/                             # ===== 全局共享资源（不计入用户配额）=====
│   ├── references/                    # 参考基因组
│   │   ├── GRCh38/
│   │   │   ├── STAR_index/
│   │   │   ├── Bowtie2_index/
│   │   │   ├── fasta/
│   │   │   └── annotation/
│   │   └── GRCm39/
│   ├── blast_db/                      # BLAST 数据库
│   ├── annotations/                   # GO, KEGG 等注释文件
│   └── bin/                           # 外部二进制工具
│
├── system/                             # ===== 系统区 =====
│   ├── .tmp/                          # 分片上传临时区
│   ├── .conda_envs/                   # Conda 环境
│   └── archive/{user_id}/            # 冷数据归档
│
└── CygnusX.yaml                        # 运行时配置（可选放此处或 data/）
```

### 3.3 路径映射（旧 → 新）

| 旧路径 | 新路径 | 迁移策略 |
|--------|--------|----------|
| `users/{uid}/raw/` | `users/{uid}/inbox/` | 重命名 + DB path 批量更新 |
| `users/{uid}/results/{flow_id}/{task_id}/` | `users/{uid}/tasks/{task_id}/work/` | DB work_dir 字段更新；旧目录 symlink |
| `users/{uid}/raw_data/{accession}/` | `users/{uid}/inbox/{accession}/` | 下载完成时直接写入 inbox |
| `users/{uid}/enrichments/{project}/{task_id}/` | `users/{uid}/tasks/{task_id}/output/` | 新任务用新路径；旧任务保留 |
| `blast/uploads/{uid}/{task_id}/` | `users/{uid}/tasks/{task_id}/input/` | 新任务用新路径 |
| `blast/results/{uid}/{task_id}/` | `users/{uid}/tasks/{task_id}/output/` | 新任务用新路径 |
| `qc/tasks/{task_id}/` | `users/{uid}/tasks/{task_id}/` | 新任务用新路径 |
| `blast/db/` | `shared/blast_db/` | 配置更新 |
| 参考基因组散落路径 | `shared/references/{genome}/` | 配置更新 |

### 3.4 任务目录规范（meta.json）

每个任务目录下的 `meta.json` 是自描述文件：

```json

  "task_id": "uuid",
  "tool": "rna_seq | atac_seq | blast | enrichment | fastq_qc | phylogenetic_tree | ...",

    "work": "30d",

    "logs": "30d"
  }
}
```

## 四、统一接口设计

### 4.1 统一文件访问 API

**核心思想**: 所有文件（无论来源）通过统一的 `file_id` 访问，消除多套下载接口。

```
# 统一文件 CRUD
GET    /api/v1/files                    # 列出用户所有文件（支持 ?source=task|inbox|workspace 过滤）
GET    /api/v1/files/{file_id}          # 文件元数据
GET    /api/v1/files/{file_id}/download # 统一下载（Content-Disposition）
GET    /api/v1/files/{file_id}/preview  # 在线预览（HTML/图片/CSV）
DELETE /api/v1/files/{file_id}          # 删除（软删除 → 30天后物理清理）

# 目录浏览
GET    /api/v1/files/tree               # 用户文件树（inbox + tasks + workspace 聚合视图）
GET    /api/v1/files/tree?path=tasks/{task_id}/output  # 子目录浏览

# 文件引用（供 AI / 工具链使用）
POST   /api/v1/files/resolve            # 解析 URI → 绝对路径（内部调用）
```

### 4.2 统一文件注册机制

**所有模块**在产生输出文件后，必须调用 `FileRegistry.register()` 将文件注册到 `file_records`：

```python
# src/cygnusx/domain/file/registry.py

class FileRegistry:
    """统一文件注册入口 — 所有工具/流程产出文件的唯一注册点。"""

    async def register(
        self,
        user_id: UUID,
        task_id: UUID | None,
        path: Path,              # 相对于 data_root 的路径
        file_type: FileType,
        display_name: str,
        source: FileSource,      # PIPELINE | TOOL | UPLOAD | DOWNLOAD | AI_CHAT
        metadata: dict | None = None,
    ) -> FileRecord:
        """注册文件，返回 FileRecord（含 file_id）。幂等：同路径重复注册返回已有记录。"""
        ...

    async def register_directory(
        self,
        user_id: UUID,
        task_id: UUID | None,
        directory: Path,
        source: FileSource,
        patterns: list[str] | None = None,  # glob 过滤
    ) -> list[FileRecord]:
        """批量注册目录下匹配的文件。"""
        ...
```

### 4.3 统一路径工厂

替代当前分散在各 Service 中的路径拼接逻辑：

```python
# src/cygnusx/infrastructure/storage/path_factory.py

class StoragePathFactory:
    """统一路径工厂 — 所有磁盘路径的唯一生成点。"""

    def __init__(self, config: StorageConfig):
        self._root = Path(config.data_root)
        self._users_subdir = config.users_subdir

    # --- 用户区 ---
    def user_root(self, user_id: str) -> Path:
        return self._root / self._users_subdir / user_id

    def inbox_dir(self, user_id: str) -> Path:
        return self.user_root(user_id) / "inbox"

    def task_dir(self, user_id: str, task_id: str) -> Path:
        return self.user_root(user_id) / "tasks" / task_id

    def task_input_dir(self, user_id: str, task_id: str) -> Path:
        return self.task_dir(user_id, task_id) / "input"

    def task_output_dir(self, user_id: str, task_id: str) -> Path:
        return self.task_dir(user_id, task_id) / "output"

    def task_work_dir(self, user_id: str, task_id: str) -> Path:
        return self.task_dir(user_id, task_id) / "work"

    def task_logs_dir(self, user_id: str, task_id: str) -> Path:
        return self.task_dir(user_id, task_id) / "logs"

    def workspace_dir(self, user_id: str) -> Path:
        return self.user_root(user_id) / "workspace"

    def downloads_dir(self, user_id: str) -> Path:
        return self.user_root(user_id) / "downloads"

    # --- 共享区 ---
    def shared_root(self) -> Path:
        return self._root / "shared"

    def reference_dir(self, genome: str) -> Path:
        return self.shared_root() / "references" / genome

    def blast_db_dir(self) -> Path:
        return self.shared_root() / "blast_db"

    # --- 系统区 ---
    def tmp_dir(self, upload_id: str) -> Path:
        return self._root / "system" / ".tmp" / upload_id

    def archive_dir(self, user_id: str) -> Path:
        return self._root / "system" / "archive" / user_id
```

### 4.4 统一文件 URI 协议

扩展现有 `ManagedFileResolver`，覆盖所有文件来源：

```
file://{file_id}                    # 通过 file_records.id 引用（推荐）
task://{task_id}/output/{rel_path}  # 任务输出文件
inbox://{file_id}                   # 用户上传文件（file:// 的别名）
shared://references/{genome}/{path} # 共享参考资源（只读）
```

### 4.5 统一配额计算

```python
# 配额 = users/{uid}/ 下所有文件的总大小（含 inbox + tasks + workspace + downloads）
# 不计入: shared/, system/, 已归档到 archive/ 的文件

async def calculate_user_usage(user_id: str) -> int:
    """基于 file_records 表 SUM(size) 计算，而非 du 扫描。"""
    # 前提：所有文件都已注册到 file_records
    return await file_repo.sum_size_by_user(user_id, status="active")
```

## 五、数据库 Schema 优化

### 5.1 `file_records` 表扩展

```sql
ALTER TABLE file_records ADD COLUMN source VARCHAR(32) NOT NULL DEFAULT 'upload';
-- source: upload | pipeline | blast | enrichment | fastq_qc | download | ai_chat | sandbox

ALTER TABLE file_records ADD COLUMN task_id UUID REFERENCES tasks(id);
-- 关联产生此文件的任务（可为空，如手动上传）

ALTER TABLE file_records ADD COLUMN project_slug VARCHAR(128);
-- 所属项目（可为空）

ALTER TABLE file_records ADD COLUMN lifecycle_status VARCHAR(16) NOT NULL DEFAULT 'active';
-- lifecycle_status: active | archived | pending_delete

ALTER TABLE file_records ADD COLUMN cleanup_after TIMESTAMP;
-- 自动清理时间（由 cleanup_policy 计算）

CREATE INDEX idx_file_records_user_source ON file_records(user_id, source);
CREATE INDEX idx_file_records_task ON file_records(task_id);
CREATE INDEX idx_file_records_lifecycle ON file_records(lifecycle_status, cleanup_after);
```

### 5.2 废弃/合并的表

| 现有表 | 处理方式 |
|--------|----------|
| `blast_tasks.result_path` | 保留任务状态管理，但结果文件统一注册到 `file_records` |
| `report_files` | 保留（报告是文件的特殊视图），但 `path` 字段改为 `file_id` 外键 |
| 各工具独立的结果路径字段 | 逐步迁移：新任务写 `file_records`，旧任务保留兼容读取 |

- 最终产物的**注册**（`data_deliver/` 下的文件注册到 `file_records`）

## 十、风险与注意事项

| 风险 | 缓解措施 |
|------|----------|
| 旧任务路径失效 | Phase 2 期间新旧路径并存；读取时先查 DB 再回退旧路径 |
| 迁移期间服务中断 | 迁移脚本支持增量、可重入；symlink 过渡 |
| 配额突变（补注册后） | 迁移前通知用户；首次补注册不触发超额告警 |
| Pipeline 兼容性 | Pipeline 内部不感知平台路径变更，仅 workdir 位置变化 |
| 并发写入冲突 | `FileRegistry.register()` 使用 `ON CONFLICT (storage_path) DO NOTHING` 幂等 |
