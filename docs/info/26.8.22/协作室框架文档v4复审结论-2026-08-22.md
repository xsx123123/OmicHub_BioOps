## 七、N-b 默认 CI 路径实施方案

- **本地验证**：已修复 `tests/e2e/agentteams/test_live_foundation_e2e.py` 中 E2E-9 的 Bridge URL 双写 `/v1` bug（路径从 `/v1/cases/...` 改为 `/cases/...`）。使用你提供的 `.env` 在本地真实栈运行，**3/3 passed**（E2E-7 / E2E-2 / E2E-9）。
- **CI 产物**：已新增 `.github/workflows/agentteams-live-e2e.yml`，触发方式为 `workflow_dispatch`（手动）+ 预留 `schedule` 注释，默认不接入 `pull_request`。

### 7.1 CI workflow 已落地的步骤

该 workflow 会：
1. 从 GitHub Secrets 写入 `.env` 与 `deploy/agentteams/bridge.env`。
2. 按当前 runner 用户设置 `PUID`/`PGID`，创建 `CYGNUSX_DATA_ROOT` 下所需目录。
3. 创建跨栈外部网络（`cygnusx_net`、`cygnusx-sandbox-net`、`cygnusx_bridge_gateway`、`matrix-dev_default`）与外部卷（`cygnusx_embed`）。
4. 启动主栈 `web` / `db` / `cache` / `minio` / `minio-init` 与 Bridge 栈 `cygnusx-agentteams-bridge` / `cygnusx-agentteams-state`，并 `--wait` 健康检查。
5. 在 `cygnusx-web` 容器内执行 `scripts/init_demo_user.py`，再通过 `/api/v1/auth/login` 获取 `access_token`。
6. 运行 `pytest tests/e2e/agentteams/test_live_foundation_e2e.py -v`。
7. 失败时收集 `cygnusx-web`、`cygnusx-agentteams-bridge`、`cygnusx-agentteams-state` 日志。

### 7.2 需配置的 GitHub Secrets

在仓库 **Settings → Secrets and variables → Actions** 中新增：

| Secret | 内容要求 |
|---|---|
| `CYGNUSX_DOT_ENV` | 完整 `.env` 文件内容（你刚才粘贴的内容）。workflow 会原样写入仓库根目录 `.env`。确保其中 `AGENTTEAMS_BRIDGE_MANAGER_TOKEN` 与 `bridge.env` 中 `bioops-manager` token 一致。 |
| `AGENTTEAMS_BRIDGE_ENV` | 完整 `deploy/agentteams/bridge.env` 文件内容。其中 `BRIDGE_IDENTITIES` 里的 `bioops-manager` token 需与 `.env` 中 `AGENTTEAMS_BRIDGE_MANAGER_TOKEN` 一致；`BRIDGE_MINIO_ACCESS_KEY` / `BRIDGE_MINIO_SECRET_KEY` 与 `.env` 中 MinIO 凭证一致。 |
| `AGENTTEAMS_E2E_MANAGER_TOKEN` | 与 `bridge.env` 中 `bioops-manager` token 相同，供 pytest 访问 Bridge `/cases/.../events`。 |

### 7.3 后续推进条件

- **第一步**：配置上述 3 个 Secrets 后，在 GitHub Actions 页面手动触发一次 `.github/workflows/agentteams-live-e2e.yml`，确认 3/3 green。
- **第二步**：跑稳 3~5 次后，可取消 workflow 中 `schedule` 的注释，开启夜间回归。
- **第三步**：只有夜间回归稳定且启动耗时可接受（当前本地约 30s，CI 首次构建镜像可能 5~10min）后，才评估并入 `.github/workflows/ci.yml` 作为默认 job；默认路径建议加 `if: github.repository == '...' && github.event_name != 'pull_request'` 等保护，避免 forks/external PR 因缺 secrets 失败。

### 7.4 已知限制

- 当前 workflow 仅覆盖 E2E-7/2/9（房间事件 / limit / 游标对账），不启动 Worker profile，因此**不覆盖审批→执行→交付段**（步骤 4）。
- 审批→执行→交付段需要真实 Worker 执行计算任务，需在 workflow 中加入 `agentteams-acceptance` 或真实 Worker profile，并额外注入对应 Worker tokens，属于步骤 4 的验收范围。
