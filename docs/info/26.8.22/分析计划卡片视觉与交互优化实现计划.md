# 分析计划卡片（Plan 模式）视觉与交互优化实现计划

> 版本：v1.0（2026-08-22）
> 输入：用户截图 2 张（智能助手工作台 · Plan 模式"分析计划"卡片现状）
> 本文档 = 评估结论 + 问题清单与优化 Spec + 分阶段实现 + 可直接粘贴给编码 Agent 的提示词 + 验收清单
> 关联文档：《AskUser澄清卡片视觉优化实现计划》（同平台卡片组件，设计语言与变量体系一脉相承）

---

## 一、背景与评估结论

### 1.1 现状（截图证据）

Plan 模式触发后，对话区中部渲染"分析计划"卡片（标题 + "7 个步骤" + 纵向时间线步骤列表，首步"进行中"、其余"待执行"）。现状问题：

1. 卡片横向铺满消息列，而底部聊天输入框有更窄的限宽与水平边距，**两者左右边界明显错位**；
2. 卡片**无容器样式**（无描边、无背景、无投影），像一段裸文本浮在消息区，与下方输入框视觉割裂，不成整体；
3. **无折叠能力**，7 个步骤全部平铺，长计划占满首屏；
4. 视觉层级平：状态文字"待执行"浅灰对比度偏低、"进行中"不够突出、无进度量化指示（只有"7 个步骤"静态文字）。

### 1.2 评估 Verdict：用户四点方向全部正确，采纳

业界约定（《AskUser澄清卡片视觉优化实现计划》调研已查证）：Cursor 2.1 Plan Mode、Claude Code 计划面板均为"**贴着输入框的可折叠面板**"形态——计划/待办作为 composer 的附着面板，与输入框等宽、可收起为摘要行。用户的四点诉求与该约定完全一致：

| 用户诉求 | Verdict | 依据 |
|---|---|---|
| ① 卡片宽度与输入框一致 | 对 | Cursor/Claude Code 计划面板均与 composer 等宽 |
| ② 卡片与输入框一体感 | 对 | composer 附着面板是主流形态；裸文本无容器是主要"难看"来源 |
| ③ 折叠/展开按钮 | 对 | 长计划霸屏是 AI IDE 通病，折叠为摘要行是标准解法 |
| ④ 整体显示样式优化 | 对 | 状态色彩体系 + 进度 chip + 时间线细节，对齐平台既有卡片规范 |

### 1.3 目标

不改计划数据结构、不改步骤状态流转与轮询/流式更新逻辑，只改布局、容器视觉与折叠交互，使 Plan 卡片成为"输入框的附着面板"：等宽对齐、容器成组、可折叠、状态层级清晰。

## 二、问题清单与优化 Spec

### 问题 1：卡片宽度与输入框不对齐

**现状**：卡片铺满消息列，输入框限宽更窄，左右边界错位，视觉重心散。

**Spec**：

- Plan 卡片复用与底部输入框**完全相同的宽度约束**：同一限宽 wrapper，或相同的 max-width + 水平 padding，左右边界像素级对齐；
- 若卡片渲染在消息流内部、受消息气泡宽度约束，优先最小改动：给 plan 类型消息容器加"对齐输入框宽度"的专用类，**不动消息流整体布局与其他消息类型**；
- 桌面与移动断点下都保持对齐，移动端不出现横向滚动。

**预期效果**：卡片左右边线与输入框左右边线完全对齐，纵轴统一。

### 问题 2：卡片与输入框缺乏一体感

**现状**：卡片无描边/背景/阴影，与输入框视觉割裂。

**Spec**：

- 定位：输入框正上方的"附着面板"，与输入框间距 8px；
- 容器：1px 边框（浅色主题 rgba(0,0,0,0.06~0.08)，用现有 --neutral-* 变量）；圆角 12px（与输入框圆角同族，输入框若为 16px 则卡片 12px 形成嵌套对齐）；背景 var(--chat-ai-card) 或等价变量；柔和弥散投影（var(--chat-shadow-sm) 或 0 1px 2px rgba(0,0,0,0.04), 0 4px 12px rgba(0,0,0,0.04)）；
- **不做**"卡片叠进输入框"的连体结构，保持独立卡片但视觉成组。

**预期效果**：一眼看出"计划面板 + 输入框"是一个工作区整体。

### 问题 3：缺少折叠/展开

**现状**：步骤全部平铺，无法收起。

**Spec**：

- 标题行整行可点击切换；右侧 chevron 按钮 24×24px、圆角 6px、hover 底色 rgba(0,0,0,0.04)，chevron 随状态旋转 180°，过渡 200ms；
- 折叠态单行摘要：「分析计划 · 已完成 X/N · 当前：{当前步骤标题}」，过长 ellipsis 截断；全部完成时显示「分析计划 · N/N 已完成 ✓」；
- 高度动画：grid-template-rows 0fr ↔ 1fr（或 max-height 过渡），250ms ease-out；prefers-reduced-motion 开启时直接切换无动画；
- 折叠状态组件内保持（会话内记忆即可）；计划全部完成后默认自动折叠一次，用户手动展开后不再自动折叠。

**预期效果**：长计划不再霸屏；完成后的计划自动收成一行摘要，可回看。

### 问题 4：视觉细节整体优化

**Spec**：

- 标题行：标题 14px / 字重 600；右侧"N 个步骤"改为进度 chip（"X/N"，12px，圆角 999px，背景 color-mix(in srgb, var(--chat-accent) 12%, transparent)，文字 var(--chat-accent)）；
- 状态色彩体系：进行中 = var(--chat-accent)，节点实心 + 外环 box-shadow: 0 0 0 3px color-mix(in srgb, var(--chat-accent) 15%, transparent)；待执行文字不得浅于 #98a2b3（对比度 ≥ 4.5:1）；已完成 = 节点变 ✓ + 文字 var(--neutral-text-2)；
- 时间线：连接线 2px、rgba(0,0,0,0.08)；节点与步骤文字首行基线对齐；进行中节点呼吸脉动（opacity 1 ↔ 0.3，周期 1.2s，ease-in-out，仅用 opacity）；
- 密度：步骤行 padding 8px 12px，收窄行间距（现状偏稀）；步骤文字 13~14px，当前步骤字重 500、其余 400。

## 三、分阶段实现

| 阶段 | 内容 | 风险 | 独立可验 |
|---|---|---|---|
| 阶段 1 | 问题 1 + 2：宽度对齐 + 容器样式（纯 CSS/布局） | 低 | 卡片与输入框左右边线对齐、有明确卡片容器 |
| 阶段 2 | 问题 3：折叠/展开交互（轻量组件状态） | 低 | 点击收起为摘要行、展开动画顺滑、完成后自动折叠 |
| 阶段 3 | 问题 4：进度 chip、状态色彩、时间线、密度 | 极低 | 逐条对照 spec 截图确认 |

阶段 1 无依赖先行；阶段 2 在阶段 1 合入后进行（折叠摘要依赖容器结构）；阶段 3 可与阶段 2 并行。

## 六、风险与回退

| 风险 | 说明 | 回退 |
|---|---|---|
| 卡片嵌在消息流气泡宽度约束内 | 宽度对齐可能需要调整消息容器层级 | 最小改动方案：plan 消息容器加专用对齐类；仍不行则本期只做问题 2/3/4，宽度对齐单列一轮 |
| grid 0fr/1fr 高度动画兼容性 | 旧内核浏览器不支持 grid-template-rows 动画 | 回退 max-height 过渡（预设一个足够大的 max-height） |
| 自动折叠时机误伤 | 用户正盯着计划看时被收起 | 仅在全部完成后折叠一次；记录用户手动展开状态，不再自动折叠 |
| 与 AskUser 卡片样式体系打架 | 同页多卡片组件风格不一致 | 复用同一组 --chat-* / --neutral-* 变量，不新造色值 |
| 全部回退 | 任何阶段出问题 | 三个阶段独立提交，单独 revert；卡片基础展示不依赖任何新样式 |
