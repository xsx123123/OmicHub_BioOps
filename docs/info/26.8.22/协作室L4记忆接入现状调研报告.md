## 0. 执行摘要

- **自动读取面：未找到 L4 房间调用 `AgentMemoryService.build_prompt_context*`。** Manager prompt 当前由 Case 事件、用户 `preferences.agentteams` 和房间规则组成，没有证据证明会自动注入 `<user_memory>`。
- **主动写入面：配置可用，实际调用需按分支核验。** `agentteams-manager` 声明 `memory` tool pack；工具最终进入统一 ToolBridge/`AgentMemoryService`，敏感内容校验仍生效。
- **分区存在设计意图与 v2 实际行为差异。** `profile/preference` 保存工具传入 `agent_id=None`，但 v2 `AgentMemoryService` 写入 `memory_facts` 时会把它归一为 `""`；v2 搜索又按当前 Agent ID 查询，因此当前实现不能证明 L2/L4 真正共享这些事实。
- **settle 存在潜在覆盖风险。** 房间响应本身没有直接调用 ChatService settle enqueue，但合成会话没有被通用 settle 条件排除；若被触发，当前会话的 `agent_id` 为空字符串，Case 项目事实可能进入长期记忆。
- **L4 未找到 ChatService 的 v2 写入纪律后缀。** 普通聊天会装配该纪律，L4 使用 `AgentService.assemble_context` 和 `AgentConsultationService`，未发现同样的提示词注入。
- **Studio 文件记忆与 L4 Case 记忆未找到直接交集。** `MEMORY.md/.memory/` 由 Studio 工作区工具维护；L4 使用房间事件流、Case 血缘和 Agent memory。

置信度：**已证实**=存在当前代码调用点；**未找到**=当前代码检索范围内没有调用点；**存疑**=存在间接路径或运行时条件，需补充运行时/e2e 证据。

## 2. Q2：settle 覆盖范围

### 结论

**房间响应没有直接调用 ChatService 的 settle enqueue，但通用 settle 条件没有排除 AgentTeams 合成会话。** 这不是“当前已持续泄漏”的证据，却是必须显式封堵的潜在风险。

### 合成会话

`record_consultation_usage` 在 token 用量有效且 `requester_ref` 是合法 UUID 时创建/更新：

- `session_id = agentteams:<case_id>`；
- `user_id = requester_ref` 的 UUID 字符串；
- `status = system`；
- `mode = agentteams`；
- 构造 `ChatSessionModel` 时没有显式设置 `agent_id`，因此为 `NULL`；
- 每次有效会诊写入一条 assistant `ChatMessage` 并增加 `message_count`。

证据：`src/cygnusx/application/services/agentteams_usage_service.py:38-128`。

### settle 投递点

- 删除会话：`_enqueue_memory_summary` 在 v2 和运行时开关打开时 enqueue，不检查 `status/mode`：`src/cygnusx/application/services/chat_service.py:2021-2043`。
- 消息阈值：`_maybe_enqueue_memory_settle` 在消息数达到 `max(4, memory_settle_min_new_messages)` 时 enqueue，也不检查 `status/mode`：`src/cygnusx/application/services/chat_service.py:2045-2066`。
- 当前 `record_consultation_usage` 自己写消息，不调用 `_maybe_enqueue_memory_settle`，所以从现有房间响应路径**未找到直接投递点**。

### 若被 settle 的分区与内容

`settle_session_memory` 使用 `owner = (chat_session.user_id, chat_session.agent_id or "")`，并通过 `last_settled_message_id` 游标与 `range_key` 区间幂等：

- `src/cygnusx/infrastructure/celery_app/tasks/memory.py:223-251`
- `src/cygnusx/infrastructure/celery_app/tasks/memory.py:265-311`

因此当前合成会话若被 settle，预计写入：

```text
(user_id = requester UUID, agent_id = "")
```

settle 抽取提示词允许项目级事实（数据集、样本量、分组、分析目标）和重要决定，禁止一次性指令、凭据和隐私：`src/cygnusx/infrastructure/celery_app/tasks/memory.py:42-63`。所以：当前没有持续泄漏证据；但一旦合成会话进入 settle，Case 临时事实进入 `memory_facts` 在机制上是可能的，建议按 P1/P0 设计风险处理。

## 3. Q3：分区语义与 Agent 角色

### 实际分区规则

`src/cygnusx/application/services/agent_memory_tool_service.py:20-32` 明确规定保存工具的意图：

- `profile` / `preference` 保存：工具层传入 `agent_id=None`，设计上希望跨 Agent 共享；
- 其他 scope 保存：使用当前 `context.agent_id`；
- `search_memory` 当前直接使用 `context.agent_id`：`:103-121`；
- `update_memory_block` 要求存在当前 `context.agent_id`：`:123-140`。

不能笼统地说“所有记忆按 Agent 隔离”：

| scope/操作 | 分区 | L2/L4 共享性 |
|---|---|---|
| `profile`、`preference` 保存 | 工具层 `None`；v2 fact store 实际写为 `""` | 设计上共享，当前 v2 召回不成立 |
| `project`、`summary` 保存 | 当前 Agent ID | 默认隔离 |
| `memory_block` | 当前 Agent ID | 默认隔离 |
| `search_memory` | 当前 `context.agent_id`；v2 fact store 精确按该 ID 搜索 | 当前 v2 不会自动召回 `agent_id=""` 的共享事实 |

### L4、L2、专家 ID

- L4 Manager：`agentteams-manager`，证据：`data/ai/agentteams_manager.yaml:8`。
- L4 会诊先按目标 Agent ID 组装 context：`src/cygnusx/application/services/agent_consultation_service.py:311-327`。
- 子 Agent 工具执行上下文显式设置 `agent_id=agent_id`：`src/cygnusx/application/services/parallel_subagent_service.py:1135-1174`。
- L2 长期记忆注入使用运行时 `ctx.agent.agent_id`：`src/cygnusx/application/services/chat_service.py:6156-6159`，不能只按默认 Agent 名称推断。
- 会诊 fan-out 的 `parent_agent_id` 固定为 `agent-general`，但这不等于 Manager 的工具调用分区；实际工具上下文由子任务 `agent_id` 设置：`src/cygnusx/application/services/agent_consultation_service.py:365-384`、`src/cygnusx/application/services/parallel_subagent_service.py:1164-1168`。

### v2 共享偏好缺口

代码链路显示一个实际不一致：

1. `AgentMemoryToolService._memory_agent_id` 对 `profile/preference` 返回 `None`：`src/cygnusx/application/services/agent_memory_tool_service.py:27-31`。
2. v2 `AgentMemoryService.save_memory` 构造 `MemoryFactCreate` 时使用 `agent_id=agent_id or ""`：`src/cygnusx/application/services/agent_memory_service.py:63-76`。
3. v2 `search_memory` 使用 `PostgresFactStore.search(user_id, agent_id or "", ...)`：`src/cygnusx/application/services/agent_memory_service.py:159-174`；L4 Manager 搜索传入的是 `agentteams-manager`，不会命中空字符串分区。
4. v2 自动 prompt 召回同样按精确 Agent ID 读取 blocks/facts：`src/cygnusx/application/services/agent_memory_service.py:411-440`。

因此当前证据支持的结论是：**profile/preference 的跨 Agent 共享是工具层设计意图，但 v2 实现存在召回断裂；L2 写入的偏好不能据此认定 L4 Manager 可召回。**

### 工具包声明与实际调用

Manager 配置声明 `tool_packs: [workspace, research, memory, agentteams_case]`：`data/ai/agentteams_manager.yaml:71`。这证明工具可被运行时解析，不证明模型实际调用了 save/search。多专家角色是否可用 memory，应逐个检查其 YAML 的 `tool_packs` 与运行时 `child_tools`；`ParallelSubAgentService._prepare_child_tools` 会根据 `safe_only`、只读标记和工具 schema 过滤工具：`src/cygnusx/application/services/parallel_subagent_service.py:394-468`。

## 4. Q4：写入纪律与敏感拦截

### 结论

- **写入纪律在 L4：未找到。** `MEMORY_V2_WRITE_DISCIPLINE` 位于 `chat_service.py:1284-1289`，其装配逻辑属于普通 ChatService；L4 `AgentService.assemble_context` 未引用该常量。

- **模型是否能实际发起 save：存疑/按运行时工具过滤。** Manager 有 memory tool pack；但只读会诊的 `safe_only` 过滤可能剥离写工具，必须用运行时工具清单或 e2e 证据确认。

普通聊天的记忆工具提示词为 `MEMORY_SYSTEM_PROMPT_SUFFIX`：`src/cygnusx/application/services/chat_service.py:1276-1282`；L4 会诊的 `_build_instruction` 只生成会诊能力、证据、硬闸门和 JSON 信封约束：`src/cygnusx/application/services/agent_consultation_service.py:470-531`。

## 5. Q5：Studio ↔ L4 边界

### 结论

**当前代码未找到 Studio 文件记忆与 L4 房间/Case 的直接交集。**

- Studio 记忆正统是工作区 `MEMORY.md` 索引与 `.memory/*.md` 正文；架构证据：`ARCHITECTURE_DESIN/memory_architecture.md:221-251`。
- Studio 工具 `cygnusx_workspace_remember` 和工作区读写属于 Studio 工具链：`src/cygnusx/application/services/studio_tools.py`、`src/cygnusx/application/services/studio_context_service.py`。
- L4 房间 prompt 使用 Case 事件、文件引用、Case 状态和 Agent memory 工具；未找到 `MEMORY.md`、`.memory/` 或 `cygnusx_workspace_remember` 被 `agentteams_room_response_service.py`、`agent_consultation_service.py` 自动调用。
- L4 工作区执行路径使用 `/data/cygnusx/output/agentteams/<case_id>/<work_item_id>`：`src/cygnusx/application/services/agent_consultation_service.py:343-346`，这是产物/执行目录，不等于 Studio 的文件记忆目录。

### 语义边界

| 载体 | 当前职责 | 是否是 Case 事实源 |
|---|---|---|
| Case 事件流/血缘 | 状态、证据、产物和执行事实 | 是 |
| Agent memory | 用户偏好、项目/摘要类跨会话事实 | 否，不应替代 Case 血缘 |
| Studio `MEMORY.md/.memory` | 工作区级索引与正文 | 否，当前未接入 L4 |
| AgentTeams workdir | L4 执行产物与工具工作目录 | 否，除非通过事件/产物血缘登记 |

## 6. L4 记忆数据流图

```text
用户消息
  │
  ├─ L4 自动读取（当前未接入）
  │    room events + User.preferences[agentteams]
  │    → _build_question → AgentConsultationService
  │    → 未发现 AgentMemoryService.build_prompt_context* 注入
  │
  ├─ 模型主动写/搜（配置可用，实际调用取决于工具清单）
  │    ToolInvocationContext(user_id, agent_id, session_id)
  │    → AgentMemoryToolService → AgentMemoryService
  │    → memory_blocks / memory_facts
  │    profile/preference: 工具层 None → v2 fact agent_id=""
  │    project/summary/block: 当前 Agent ID（隔离）
  │    注意：v2 search/prompt 按当前 Agent 精确检索，
  │    因此空分区偏好当前不能被 Manager 自动召回
  │
  └─ settle 异步写（房间当前无直接 enqueue 证据）
       ChatSession(agentteams:<case_id>, user_id, agent_id=NULL)
       → settle_session_memory(session_id)
       → memory_facts(user_id, agent_id="")
       → 游标 last_settled_message_id + range_key 幂等
```

## 7. 风险登记册

| 分类 | 风险 | 证据 | 严重度 |
|---|---|---|---|
| Case 事实泄漏 | 合成会话一旦进入通用 settle，项目事实可能被抽入长期记忆 | settle 无 `mode/status/session_id` 排除；抽取提示允许项目事实 | P1，若已存在触发路径则 P0 |
| Case 事实泄漏 | settle 写入空 Agent 分区，后续语义边界不清 | `agentteams_usage_service.py` 未设置 `agent_id`；settle 使用 `or ""` | P1 |
| 跨层失忆 | L4 不自动读 `<user_memory>`，Manager 只能依赖主动 search | L4 调用链未发现 `build_prompt_context*` | P1 |
| 跨层失忆 | v2 profile/preference 保存为空分区，但搜索按当前 Agent ID，导致 L2/L4 共享偏好无法召回 | `agent_memory_tool_service.py:27-31`；`agent_memory_service.py:63-76,159-174,411-440` | P1 |

| 拦截风险 | 工具可见性与 save/search 实际可调用性未有 L4 e2e 证据 | Manager 配置声明 memory，但 safe-only 会过滤工具 | P1，当前状态存疑 |
| 其他 | Studio 文件记忆与 L4 Case 工作区缺少显式边界测试 | 当前未发现交集调用，也未发现专门断言 | P2 |

## 8. L2 / L3 / L4 接入矩阵

| 面 | L2 普通聊天 | L3 Studio | L4 AgentTeams 房间 |
|---|---|---|---|

## 9. 设计建议

1. 在 settle 入口增加明确的 AgentTeams 排除：至少按 `mode == "agentteams"`、`status == "system"` 或 `session_id.startswith("agentteams:")` 阻断。
2. 若产品决定让 L4 共享用户偏好，应在房间 prompt 装配点显式调用记忆服务，并记录 scope 与 `agent_id` 语义；不要依赖模型主动 search。
3. 将 L4 专用的记忆写入纪律放进 AgentTeams 会诊 system prompt，并保留统一 `AgentMemoryService` 敏感拦截作为最后一道服务端闸门。
4. 增加 e2e 断言：Manager/专家实际可见 memory 工具、工具调用上下文中的 `user_id/agent_id`、合成会话不会触发 settle、Case 事实不会写入 `memory_facts`。
