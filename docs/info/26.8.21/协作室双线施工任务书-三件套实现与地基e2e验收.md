## Part 2. Track B：地基 e2e 验收（主干，真实服务）

### 2.1 环境准备（一次性）

```text
【任务性质】搭建真实服务 e2e 环境并跑通套件骨架；不改业务代码。

【内容】
1. 用 compose 起全量真实服务：主后端 + Bridge + MinIO + Redis + PG +
   （可选）Matrix Gateway；Bridge 注入 BRIDGE_MINIO_* 指向真实 MinIO；
2. e2e 套件（tests/e2e/）以 HTTP/API 驱动，禁止 mock Bridge/MinIO；
3. 每条用例输出证据文件（事件流导出 /healthz SHA / 断言结果），
   归档到 evidence/e2e-<日期>/ 供人工复核；
4. 套件进 CI 默认执行（夜间或 MR 触发均可，但必须默认跑而非 opt-in）。
```

## 风险登记

| 风险 | 缓解 |
| --- | --- |
| Track B 红灯阻塞 Track A 心态 | 地基 bug 走主干 hotfix 是预期流程，不算返工 |
| 三件套分支与主干 hotfix 冲突 | 每次主干 hotfix 合入后施工分支即 rebase |
| e2e 环境本身不稳（flaky） | 每条用例失败先查环境再查代码；flaky 用例单独标记禁止一键豁免 |
| 前端手测替代服务端验证 | 手测清单只覆盖交互层；数据层以 E2E-8/9/14/16 为准 |
