## Part 1 · 背景与目标

**平台**：星尘 AI（AgentTeams 协作室 / CygnusX 平台），用户发起新对话前弹出"选择处理方式"弹窗，选择"交给星尘 AI 自动分派"或指定某位专家智能体。

**现状结构**：顶部自动分派横幅（推荐）+ 领域 tab 栏（通用 3 / 分析 9 / 编程 1 / 可视化 1 / development 2 / operations 1 / exploration 1，共 19 个智能体）+ 三列卡片栅格 + footer 提示。

**用户痛点（2026-09-22 提出）**：
1. 无法一眼看到所有智能体——必须逐个点击 7 个领域 tab 才能看全 19 个；
2. 整体感觉混乱。

**目标**：不推翻弹窗形式，重构弹窗内部信息架构（方向 A）。以下业务逻辑**一律不动**：
- 选择专家后开启新对话、当前会话可从历史恢复；
- 自动分派入口及其"推荐"定位；
- 领域数据、智能体数据本身。

## Part 3 · 业界锚点（2026 年已验证的约定）

1. **Command Palette 模式是多 item 选择器的主流解法**：标准解剖为 触发器 → 搜索框（自动聚焦）→ 分组结果（最近使用/全部/分类）→ 空状态说明，而不是分类 tab 抽屉。
2. **ChatGPT 的做法**：平静输入框 + 单一大菜单入口 + 结果导向标签 + **最近使用排在最前**；能力收敛在一个 + 菜单里，选中后以可移除 chip 显示在发送前。
3. **商店化（Coze / GPTs store：搜索 + 分类 + 卡片 + 详情页）只在智能体数量涨到几十个以上时才划算**，19 个时上商店页是杀鸡用牛刀。
4. **趋势是对话式发现**：让系统翻译用户意图，而不是要求用户先搞清平台分类学。

**结论（verdict）**：弹窗形式保留；把 tab 换成"搜索 + 全部默认 + 领域筛选 chips + 最近使用"，能力清单前置。即方向 A。

## Part 4 · 定稿方案 spec（方向 A）

### 4.1 弹窗容器
- 宽度：max-width 由现状约 1080px → `min(1120px, 92vw)`；
- 高度：取消固定高度，改为 `max-height: min(72vh, 860px)`，内容少时收矮；仅列表区独立滚动，头部/footer 固定。

### 4.2 顶部区（自动分派横幅）
- 保留"交给星尘 AI 自动分派【推荐】"及其文案、右箭头；
- 纵向 padding 压缩约 40%（现状约占弹窗 1/5 高度），浅紫填充保留，不再占一整行高亮大卡片的视觉权重。

### 4.3 搜索（新增，最高优先）
- 搜索框置于领域 chips 行**上方**，弹窗打开自动聚焦（autofocus）；
- placeholder：`搜索智能体名称、描述或能力…`；
- 匹配字段：name + description + capability 名称，不区分大小写，子串匹配即可（19 个量级无需模糊评分）；
- 搜索态：隐藏"最近使用"区与领域分组标题，结果平铺；
- 空结果态：文案「没有匹配"xxx"的智能体」+ 次级按钮「交给星尘 AI 自动分派」（点击 = 走自动分派路径）。

### 4.4 领域 chips（tab 改造）
- 领域 tab 改为筛选 chips：**单选、可点选、再点取消**；第一个 chip 为「全部 19」，默认选中；
- 计数改为中性样式：11–12px、`#9ca3af` 级灰字，**去掉红底白字徽标**；
- 分类学统一（前端做映射层，**不改后端枚举**）：

| 原值 | 映射为 | 备注 |
|------|--------|------|
| 通用 | 通用 | 不变 |
| 分析 | 分析 | 不变 |
| 编程 | 编程 | 不变 |
| 可视化 | 可视化 | 不变 |
| development | 工程 | **建议合并**：development + operations + exploration 合并显示为「工程」一类（共 4 个） |
| operations | 工程 | 同上 |
| exploration | 工程 | 同上 |

- 映射集中在单个前端常量文件（如 `agentDomainMap.ts`），一行可改回"不合并、各自中文名"（开发/运维/探索）；
- 编码 Agent 施工前必须先确认领域字段来源（前端常量还是后端返回），并在交付说明中报告；合并只影响展示层。

### 4.5 默认视图 = 全部，按领域分组
- 「全部」选中时：列表按领域分组展示，组标题 = 领域名 + 灰色计数（如 `分析 · 9`）；
- 组排序：按组内智能体数量降序（分析 > 通用 > 工程 > 编程 = 可视化）；
- 组内：紧凑卡片横排（参考 4.7），一行排满自动换行；
- 选中某个领域 chip 时：只显示该组，去掉组标题。

### 4.6 最近使用（新增）
- 位置：搜索框之下、列表之上，横向滚动小条；
- 内容：最近使用过的 4 个智能体（40px 图标 + 名称，单行小卡片）；
- 持久化：localStorage，key 如 `stardust.recentAgents`，仅存 id 数组，最多 8 条，新选择插到最前；
- 仅在非搜索态显示；无历史时不渲染该区域。

### 4.7 卡片紧凑化
- 取消固定高度：无能力行时约 64–76px，有能力 chips 时约 88–100px，宽度自适应栅格（minmax(300px, 1fr) 之流）；
- 结构：左 40px 圆角图标 → 右侧上排「名称（14px / 600）+ 领域标签（11px 灰）」→ 描述单行省略（`text-overflow: ellipsis`，title 悬浮显示全文）→ 能力 chips 行；
- 能力 chips：直接展示**前 3 个**能力名（11px、灰底圆角 chip），超出显示「+N」；点击「+N」或悬浮在卡片上时浮层列出全部能力（替代现在的纯 hover 浮层，触屏可点）；
- **删除"N 项专属能力"纯文本标签**；
- 右上 ↗ 箭头保留。

### 4.8 footer 与按钮
- 右下「暂不切换」：先确认现有行为——若仅是关闭弹窗，改文案为「取消」；若另有语义（保持当前会话不新建），保留文案但在按钮旁加说明；
- footer「选择后会开启新对话，当前会话仍可从历史记录中恢复」：保留位置，文字前加信息图标（ⓘ）提升可见性。

### 4.9 键盘导航（Command Palette 约定）
- 弹窗内 ↑ / ↓ 在候选间移动高亮，Enter 选中高亮项，Esc 关闭弹窗；
- 搜索框始终持有焦点，输入即过滤；无高亮项时 Enter 默认走自动分派（或提示无匹配，二选一，取与 4.3 空态一致的行为：Enter 无操作，显示空态）。

### 4.10 不做的事（本期负面清单）
- 不做 @ 唤起（阶段 2）、不做独立商店页（方向 C）、不改选择后开新对话的逻辑、不改自动分派算法、不动领域/智能体数据的后端定义、不改弹窗之外任何页面。

## Part 7 · 风险与回退

- **领域合并误伤**：映射层集中在一处，改回"各自中文名"只需改常量表；
- **搜索引入的性能**：19 条数据前端过滤无性能风险，禁止为此引入搜索库；
- **键盘导航与输入框焦点冲突**：↑↓ 在列表为空/无高亮时不得把焦点抢走；
- **localStorage 脏数据**：读取时做 id 有效性校验，失效 id 静默清除；
- 全部改动集中在弹窗组件 + 一个映射常量文件，回退 = git revert 单提交。
