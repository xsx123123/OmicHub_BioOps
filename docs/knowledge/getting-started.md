## 写在前面：我们与数据、与宇宙的关系

在做生命科学研究时，我们常常面对的是海量的测序数据、复杂的统计模型和漫长的分析流程。但请不要忘记，这些数据的源头——每一个碱基、每一个细胞、每一个样本——都来自和我们自身一样的星尘。

CygnusX 的设计初衷，正是希望让研究人员能够更专注地「借用」这些原子与数据，去探索生命的本质，而不是被繁琐的运维、配置和命令行所困扰。平台把复杂的组学分析流程封装成可点击、可追踪、可复用的工具，再配上一支懂生信的 AI 团队，让研究者可以像阅读文献一样轻松地完成从原始数据到发表级结果的全过程。

**CygnusX 的核心理念可以概括为三点：**

1. **让数据回归科学，让人回归思考**：把重复、机械、易错的工程操作交给平台和 AI，让研究者把精力放在科学问题本身。
2. **过程可复现，结果可审计**：每一次分析都基于 Snakemake 流程和参数快照，确保实验可复现、可追溯。
3. **知识沉淀与共享**：平台不仅是分析工具，更是实验室集体经验的载体——知识库、技能库、流程模板与 AI 助手共同构成可传承的研究基础设施。

## 什么是 CygnusX

**CygnusX** 是华中农业大学园艺林学学院自研的**私有化多组学分析平台**，面向生命科学研究团队提供一站式的测序数据分析、任务调度、结果可视化和 AI 辅助研究能力。

平台核心定位：

- **私有化部署**：数据不出内网，适合对数据安全有严格要求的实验室。
- **流程化分析**：内置主流组学分析流程，基于 Snakemake 实现可复现、可扩展的分析；流程以 YAML 声明式配置接入，新增流程无需修改后端代码。
- **Web 化操作**：无需精通命令行，通过浏览器即可完成上传、配置、运行、可视化和下载。
- **AI 深度集成**：内置「星尘 AI」助手团队，能聊天答疑、调用平台工具、在隔离沙盒里真实执行代码，还能跨会话记住你的研究偏好。
- **知识沉淀**：实验室知识库用于沉淀流程文档、使用经验、培训资料和架构说明；当前实验室知识库页面只展示 `lab` 知识库中的 5 篇文档，其他知识库由管理员控制是否参与 AI 检索。

平台以同一套应用代码支持三种部署规模：**单机实验室**（一台服务器起步）、**跨机器计算节点**（Web 控制面 + 多台 Worker）以及面向未来的 **Kubernetes 高可用集群**。核心原则是：容器负责运行环境隔离，共享存储负责数据可见性，调度器负责把计算分配到合适的机器。

## 首次使用：四步上手

### 第一步：登录平台

首次部署完成后，系统会开放 `/setup` 初始化页面，允许创建第一位管理员账号。

- 访问地址：`http://<服务器IP>:8888/setup`
- 该页面仅在系统中没有任何管理员账号时可用，创建成功后自动关闭（重复访问会返回 409）。
- 后续普通用户需由管理员在「系统管理 → 用户管理」中创建，或在开启自助注册后通过登录页注册。
- 登录地址：`http://<服务器IP>:8888/login`

首次登录后，系统会弹出迎新引导并发送一条欢迎通知，提示你前往「实验室知识库」查看更多资料。

> 🔒 小提示：为防暴力破解，同一 IP 连续 5 次输错密码会被临时封禁 15 分钟；管理员账号可开启 TOTP 两步验证。

### 第二步：准备并上传数据

进入「数据管理」页面，上传你的原始测序数据或样本信息文件。

- 支持的常见格式：`*.fastq.gz`、`*.fq.gz`、样本信息表（CSV / Excel）等。
- 每位用户拥有独立的数据目录 `/data/cygnusx/users/<你的用户ID>/`，按用途分为原始数据、结果、工作区、临时文件等子目录，互不干扰。
- 建议在上传前按照《数据目录结构说明》整理好样本目录与命名（如双端测序用 `sample_A_1.fastq.gz` / `sample_A_2.fastq.gz` 配对），便于流程自动识别。
- 数据也可以不上传：「数据下载」模块支持从 EBI / NCBI 公共数据库或 OSS / TOS / OBS 云存储**直接拉取**到平台（功能是否开启请咨询管理员）。

> 💡 小技巧：超过 5 GB 的批量样本，建议联系管理员直接将数据放到服务器共享目录后再在平台注册，避免浏览器大文件上传。

### 第三步：选择并提交分析流程

进入「分析流程中心」，浏览平台当前正式注册的流程：

- **RNA-seq 差异表达分析**（rna_seq v2.3.0）：基于 STAR + RSEM + DESeq2，适用于有分组信息的 bulk RNA-seq，输出 QC 报告、差异基因列表和可视化报告。
- **ATAC-seq 染色质可及性分析**（atac_seq v0.1.0）：基于 Bowtie2/Chromap + MACS2 + TOBIAS，输出 Peak calling、注释与差异可及性结果。

两个流程均已接入 AI 辅助：你可以直接在星尘 AI 对话中说"帮我提交一个 RNA-seq 分析"，AI 会引导你确认参数后代劳提交。单细胞转录组流程正在接入中。

选择流程后，按页面提示填写参数（参考基因组版本、分组信息、差异比较方案等）。确认无误后点击「提交任务」，平台会生成 Snakemake 工作流并分发到 Worker 执行。所有参数会保存为**参数快照**，随时可回看。

### 第四步：监控任务与下载结果

进入「任务中心」，实时查看任务状态：

| 状态 | 含义 |
|------|------|
| 等待中 | 任务已入队，正在等待 Worker 资源 |
| 运行中 | Worker 正在执行流程 |
| 成功 | 分析完成，可查看与下载结果 |
| 失败 | 执行异常，请查看实时日志排查 |
| 已取消 | 用户或管理员手动取消了任务 |

点击任务行进入「任务详情」，可查看：

- **实时日志**：流程运行输出，失败排查的第一现场；
- **参数快照**：本次任务的完整配置；
- **结果文件**：在线预览或下载（分析流程的结果按 `00.raw_data → 01.qc → 02.mapping → …` 编号目录组织，最终交付物在 `data_deliver/`）；
- 任务成功后还可进入「报告中心」查看交互式 HTML 分析报告。

## 平台模块巡礼

下面按照平台导航的顺序，逐一介绍每个模块现阶段的功能与使用要点。

### 1. 仪表盘（首页）

登录后的第一屏。提供平台运行状态概览、快捷入口卡片（RNA-seq / ATAC-seq / 数据管理 / 星尘 AI / 任务中心）和"三步开始你的分析"引导。管理员可在后台「首页入口管理」中配置显示哪些快捷入口。

### 2. 数据管理

**理念**：一份数据、多处复用、统一入口。数据不只是文件，而是带有元信息、可被检索、可被复用的实验室资产。

**功能与用法**：

1. 左侧导航「数据管理」进入个人文件空间，按目录浏览、上传、新建文件夹、重命名、移动、下载、删除。
2. 上传的大文件走分片上传，中断可续传；聊天中上传的附件也会归档在会话目录。
3. 提交分析任务时，可在参数页直接点选已上传的数据目录，无需手输路径。

**注意**：删除操作通常不可恢复；请遵守实验室数据规范，勿越权访问他人目录。

### 3. 数据下载（公共数据库 & 云存储）

不用先把数据下到个人电脑再传平台——在「数据下载」中登记 EBI / NCBI 的登录号或云存储（OSS / TOS / OBS）地址，平台会在后台直接拉取到服务器。下载任务同样出现在任务中心，进度可见；下载完成的文件自动登记进你的数据目录。该功能是否启用由管理员通过开关控制。

### 4. 分析流程中心

**理念**：流程即代码，流程即服务。把实验室的最佳实践沉淀为可复用的标准化流程，而不是每个人重复造轮子。

**功能与用法**：

1. 浏览流程卡片，进入详情页阅读流程说明、输入要求、输出结果和参数说明。
2. 点击「新建任务」配置参数并提交；流程以 YAML 声明式配置注册，管理员新增流程后可热重载生效，无需重启平台。
3. 每个流程都配有 AI 助手入口：在流程详情页可直接向 AI 咨询该流程的适用场景与参数含义。

**注意**：不同流程对输入格式要求不同，提交前务必阅读「输入要求」；参数提交后生成快照，保证可复现。

### 5. 任务中心与工作流监控

**理念**：透明、可控、可追溯。任务的完整生命周期（提交 → 排队 → 运行 → 成功/失败 → 归档）全部可视化。

除了常规的任务列表与详情，平台还提供**工作流监控**视图，以更细的粒度观察流程内部各步骤（Snakemake 规则级别）的执行情况。失败任务可查看日志后重试；长时间「等待中」请先确认 Worker 节点是否在线（或联系管理员）。

### 6. 报告中心

流程产出的交互式 HTML 报告集中在这里查看与分享，无需下载后本地打开。报告内通常整合了 QC、比对统计、差异分析结果与图表，可直接用于组会汇报。

### 7. 生信工具箱

平台把高频的生信小工具全部 Web 化，统一收录在「工具中心」。每个工具独立成页，上传即用：

| 工具 | 功能 |
|------|------|
| FASTQ 质控 | 原始测序数据质量评估 |
| BLAST 比对 | 序列相似性搜索，管理员维护本地 BLAST 数据库，任务历史可查 |
| JBrowse 基因组浏览器 | 在基因组坐标上查看 BigWig / BED / GFF 等轨道（详见下文） |
| 绘图工作台 | 上传数据在线绘制常见科研图表 |
| 火山图 | 差异表达结果可视化 |
| KEGG 富集分析 | 差异基因通路富集 |
| DEG 分析 | 表达矩阵差异分析（在线 DESeq2/edgeR） |
| 序列操作器 | 序列提取、反向互补、翻译等 |
| PrimerForge 引物设计 | 引物设计与评估 |
| 格式转换器 | 常见生信格式互转 |
| 基因 ID 转换器 | Gene Symbol / Ensembl / Entrez 等 ID 互转 |
| 湿实验计算器 | 浓度换算、体系配制等湿实验常用计算 |
| Venn / UpSet 图 | 多组基因集合交集可视化 |
| 系统发育树 | 构建与展示进化树 |
| 基因表达浏览器 | 交互式浏览表达矩阵 |
| 曼哈顿图 | GWAS / 全基因组显著性可视化 |
| 云端终端 | 受控的 Web 命令行（详见下文） |

**理念**：保留灵活性，但不过度依赖命令行。工具箱里的大部分工具也可以被星尘 AI 直接调用——你可以对 AI 说"用这个表达矩阵画一张火山图"，AI 会在后台调用工具并把图表回传到对话中。

**注意**：富集分析与 ID 转换需要注意基因 ID 类型与物种数据库匹配；图表可导出发表级格式，请按期刊要求微调。

### 8. 数据库与参考资源

- **统一数据库入口**：平台主导航中的「数据库」用于管理和浏览参考基因组、物种基因资源等数据库资产；旧的「参考基因组」路径仍保留兼容跳转。
- **参考基因组**：平台统一维护参考基因组 FASTA 与 GFF3 注释（存放于共享数据区），供分析流程和 JBrowse 使用；新增资源由管理员配置后生效。
- **物种基因数据库**：按物种浏览基因信息，并逐步接入后端检索服务；具体物种和数据版本以数据库页面当前展示为准。

### 9. JBrowse 2 基因组浏览器

**理念**：从表格到基因组的多尺度观察——一个 Peak 落在哪个基因附近？一个变异位于哪个外显子？在浏览器里直接看。

**用法**：在任务结果或工具中心打开 JBrowse，通过搜索框输入基因名或坐标（如 `chr1:100000-200000`）定位；切换比对覆盖度、Peak、基因注释等轨道；缩放平移查看不同尺度。

**注意**：基因组轨道数据接口仅限内网访问（公网部署需 VPN）；大 BAM 建议转成 BigWig 查看覆盖度；不同基因组版本坐标不兼容，注意与分析结果保持同一版本。

### 10. 云端终端与受控执行环境

位于工具中心的 Web Shell，无需 SSH 登录服务器即可完成临时查看与调试：浏览器内 xterm.js 连接到隔离的终端容器，预装 samtools、bcftools、bedtools、fastqc、seqkit、python3 等常用工具。原「代码沙盒」入口已统一收敛到工具中心的云端终端；`/sandbox` 仅保留兼容跳转。

**注意**：终端需管理员授权（未授权用户会看到锁定提示）；会话有资源与时长限制，超时后会被回收；请勿执行破坏性操作；终端操作和服务日志可能被审计记录。

### 11. 实验室知识库

**理念**：把经验留下来，把门槛降下去。实验室最重要的资产不仅是服务器和代码，更是成员积累的使用经验、踩过的坑、形成的规范。

**功能与用法**：

- 树形目录浏览 + 沉浸式 Markdown 阅读；
- 有权限的用户可在线编辑、新建文章，支持拖拽/粘贴上传图片（png/jpg/gif/svg/webp，单张 ≤10MB）；
- 知识库内容同时是 AI 的检索来源——在星尘 AI 里问平台使用问题，AI 可通过 `knowledge_search` 检索已发布且允许 AI 检索的知识库。
- 当前页面只展示 `lab` 知识库的 5 篇文档；管理员可在「AI 配置中心 → 资源中心 → 知识库」中分别控制「在实验室知识库页面展示」「允许 AI 检索」和「启用该知识库」三个开关。
- 其他知识库可以保持不在页面展示，但仍允许 AI 检索；关闭「启用该知识库」时，页面展示和 AI 检索都会失效。

**当前页面配套文档**：《数据目录结构说明》《ATAC-seq 实验指南》《RNA-seq 分析小贴士》等 `lab` 文档。单细胞等专题资料属于独立知识库，不会自动出现在本页面；是否开放给 AI 检索由管理员配置。

### 12. 团队协作室

「团队协作室」是面向复杂分析案例的独立协作入口。一个 Case 对应一个协作房间，用户可以在房间内查看管理 Agent 与专业 Agent 的轮流发言、工具调用过程、执行状态、审计事件和最终产物。

- 适合需要多个角色共同完成预检、方案确认、执行和交付的分析任务；
- 房间内的 Agent 可按权限使用只读数据工具、沙箱、MCP 和 Skill，工具过程会实时投影到事件流；
- Case 支持创建、确认、修订、拒绝、重试和状态收敛，相关产物可在案例详情中查看；
- 当前采用「一 Case 一房」模型，不等同于开放式群聊；是否开放入口由管理员和部署配置决定。

普通问题仍建议使用「AI 助手」，需要真实代码执行和文件产出使用「AI 工作台」；只有需要多角色围绕同一案例协作时才使用团队协作室。

### 13. 饼干积分

**理念**：公平使用计算资源。通过「饼干 🍪」这一虚拟货币把计算资源消耗量化，让每个人对自己的资源使用有清晰认知，也为实验室评估任务真实成本、规划硬件扩容提供数据。

**用法**：

- 个人中心查看余额、消费与获取记录；
- 提交任务和调用 AI 都会按规则消耗饼干（AI 按 token 用量折算），页面会提示本次预计消耗；
- 余额不足时无法提交新任务，请联系管理员充值。

**注意**：饼干仅用于平台内部资源核算，无实际货币价值。

### 14. 系统管理（管理员）

管理员在后台管理：用户与角色、**模块权限**（可按用户勾选允许使用的模块，如 AI 助手 / AI 工作台，未授权用户会看到锁定占位页）、AI Provider 与 Agent 配置、技能与 MCP 管理、知识库资源与检索范围、饼干定价与充值、公告通知、平台参数配置、会话日志审计与 AI 用量指标仪表盘。

## 星尘 AI：平台的智能核心 ⭐

这是 CygnusX 投入最多、也最值得你花时间体验的部分。平台的 AI 不是挂在角落的聊天框，而是一支**懂平台、有工具、能动手、有记忆**的 AI 团队。输入框下那句提示语正是它的自我定位：

> "以上星尘由硅基网络演算，请以碳基智慧感知！"

### 一个入口，一支专家团队

在「AI 助手」页面与 AI 对话，默认进入**智能助手（统一路由入口）**：你只管用自然语言描述需求，它会自动判断并把对话转接给最合适的专家。你也可以在侧栏直接选择某位专家。当前内置的助手阵容：

| 助手 | 擅长领域 |
|------|----------|
| 🧭 智能助手 | 统一入口，自动识别需求并转接专家 |
| 通用助手 | 日常科研问答、文件管理、记忆与检索 |
| RNA-seq 分析师 | 转录组差异表达、富集分析与通路解读 |
| 单细胞分析师 | 单细胞质控、聚类、注释与下游分析（背后还有上游/整合/高级注释三位细分专家支撑） |
| 代码助手 | 生信脚本编写、调试与沙盒执行一体化 |
| 可视化助手 | 把数据变成 publication-ready 图表（内置多套科研配色） |
| MCP 构建师 | 按自然语言需求自动规划、生成、测试并注册新的 AI 工具 |
| 傻妞 | 彩蛋助手，来自 2060 年的华人牌手机，拥有 10 种表情模式 😉 |

所有对话均为**逐 token 流式输出**（SSE），长回复体验接近真实对话；AI 的思考过程、工具调用过程在对话中透明可见。

### AI 不只会聊天：它能调用整个平台

星尘 AI 通过平台内置工具、MCP 服务和 Agent 技能与平台深度联动。对话中你可以直接让它：

- **查询平台状态**："我的 RNA-seq 任务跑完了吗？"——AI 查询任务中心后回答；
- **提交分析流程**：AI 引导你确认参数后提交 RNA-seq / ATAC-seq 任务；
- **使用工具箱**：画火山图、跑富集、格式转换等，结果以图表卡片回传对话；
- **操作工作区文件**：列目录、读取、搜索你授权范围内的文件；
- **检索知识库**：平台使用问题先查知识库再回答；
- **联网搜索**：问"最新 / 今天 / 研究进展"类问题时自动检索网络；
- **读取你上传的文件**：在聊天框直接上传数据文件（CSV、表达矩阵等），AI 即可读取分析——文件按会话和用户隔离，不会跨会话泄露。

普通聊天会按需挂载当前 Agent 有权限使用的工具；Studio 会进一步按需加载已绑定的 Skill 和 MCP 能力，不会把全部工具说明、命令和环境变量一次性塞进上下文。工具调用过程会以流式事件展示，便于你了解 AI 正在做什么：当工具完成后，系统会把结果回灌给 AI 再继续分析；工具失败会明确说明失败，不会伪装成已完成。

在「团队协作室」中，讨论型问题默认由 Manager 会诊，不会为了“看起来在执行”而强行调用工具；明确要求读取、查看、检索或只读复核时，才会进入受控工具执行。若缺少文件、路径或关键参数，系统会先通过澄清卡片向你确认。

当 AI 缺少关键信息时，它会弹出**结构化澄清卡片**向你确认，而不是瞎猜——看到卡片选择或补充即可。

### AI 有记忆

平台为 AI 接入了长期记忆引擎（mem0 v2，已上线）：

- 你可以主动告诉 AI 偏好，例如"我习惯用 ggplot2 画图""我的物种是拟南芥"；
- 这些记忆跨会话保留，之后的对话会自动带上；
- 记忆按用户严格隔离，支持更新与遗忘（可以让 AI"忘掉"某条记忆）。

短期上下文同样有保护：历史消息超过窗口时会自动压缩摘要，关键信息不丢失。

### OmicStudio：AI 的代码执行工作台

「AI 工作台」（Studio）是比聊天更进一步的模式：**给 AI 一个真实的沙盒环境，让它真的动手跑代码、处理数据、产出文件**。

- 三栏布局：左侧对话，中间文件树，右侧产物面板，并带实时 Plan 待办和沙盒状态；
- 每个会话独享隔离的 Docker 沙盒容器，默认 2 核 / 4GB 内存 / 单步 600 秒上限；可在沙盒内运行 Python / R 代码及生信工具，产物会登记到工作台；
- 沙盒默认断网；需要安装依赖时只能通过受控的域名白名单代理，平台 Web 与其他用户目录不会直接暴露给沙盒；
- AI 可以把你的数据导入沙盒、写代码执行、把图表和结果文件登记为产物，你随时下载；
- 支持把分析计划拆成待办清单（Plan），一步步执行、逐项确认；
- 支持会话分享与导出：分享链接为只读、可撤销且最长 30 天，公开视图只展示对话和 `output/` 产物元数据，不暴露输入数据、平台挂载或执行入口；
- 管理员可将会话工作区中的合规脚本提炼为全局 Skill；该操作有文件类型、大小、路径和疑似密钥检查，并需要显式确认。

**什么时候用聊天，什么时候用工作台？** 问答、咨询、查状态、小工具调用 → 聊天；需要真实计算、批量处理数据、迭代调试代码、产出文件 → 工作台。工作台适合执行和产出，但不等于开放式服务器终端，所有代码都在受限沙盒内运行。

### 技能（Skills）：给 AI 装上"专业手册"

技能是遵循 Agent Skills 规范的**可插拔知识/能力包**。每个技能是一个带 `SKILL.md` 的小目录，分三层按需加载（索引 → 正文 → 资源），不占用无谓的上下文。

- 平台内置**技能市场**：差异表达、富集分析、数据清洗、ATAC 工具、BLAST、数据交付等技能包可直接安装；
- 技能有纯知识型（参考表、规范文档）和可执行型（附带 R/Python 脚本，AI 在沙盒中调用）两种；
- 安装方式灵活：市场安装、GitHub 导入、zip 上传、JSON 粘贴；
- 管理员可以把技能绑定给特定 Agent——例如给单细胞分析师装上细胞注释参考技能。

### MCP 与 MCP 构建师：AI 的工具插座

**MCP（Model Context Protocol）是什么？** 可以理解为 AI 的"标准工具插座"：任何工具只要按 MCP 协议封装，AI 就能即插即用地调用，无需为每个工具单独开发对接。

平台的工具体系分三层：

1. **平台内置工具**：任务查询、流程提交、文件操作、知识库检索、工具箱调用等能力由后端统一注册和授权；
2. **外部 MCP Server**：管理员可注册第三方 MCP 服务（SSE / stdio），按 Agent 绑定后供 AI 使用；MCP 定义和凭证由主后端管理，Worker 不直接持有上游凭证；
3. **MCP 构建师**：这是平台的特色能力——你用自然语言描述需求，AI 自动规划、生成、静态检查、沙箱测试并形成候选工具。

MCP 构建师的工作流是：规划 → 搜索 → 编码 → 沙箱测试 → 文档 → 候选注册。生成的代码必须通过静态安全检查并在隔离沙箱中测试；新工具先以实验性候选状态存在，**正式发布需要管理员审核**；所有版本可审计、可回滚，构建师不会代替管理员启用工具。

> 🛡️ 安全红线：MCP 构建师只负责在沙箱里写代码和测试，**永远不会代为发布**——是否启用由人决定。

### 多 Agent 协作：一位专家不够时

平台支持多种协作形态（部分默认关闭，由管理员按灰度开启）：

- **专家转接（Handoff）**：对话中 AI 判断需要换专家时，会带着交接摘要自动转交；
- **并行子 Agent**：一个复杂问题拆成多个独立子任务，派给多个子 Agent **并行**处理后汇总——按 Agent 白名单和平台开关灰度启用，子 Agent 不能替父会话向用户提问或切换会话控制权；
- **多专家会诊**：多个专家对同一问题各自给出意见后汇总——默认关闭；
- **多智能体编排器（MAS）**：把"下载数据 → 跑流程 → 画图"这类复合意图编排成可审计的执行计划，用户确认后多节点执行——⚠️ 已实现但默认关闭，属于进阶能力；
- **AgentTeams 团队协作室**：从侧边栏进入独立聊天室，以一个 Case 为单位组织多角色协作；当前 M1–M6 已实施，支持 Case 生命周期、实时事件、Agent 发言、工具过程投影、产物和会话关联。平台采用“一 Case 一房”，是否开放由管理员和部署配置决定。

### AI 使用技巧

1. **不确定问谁就直接问**——智能助手会自动转接最合适的专家；
2. **把文件直接拖进聊天框**——比描述数据内容高效得多；
3. **主动告诉 AI 你的偏好和背景**（物种、习惯的 R/Python 包）——它记得住，下次自动用上；
4. **复杂任务让它先列计划**——"先给我一个分析方案，我确认后再执行"；
5. **要出图、要算数就上工作台**（Studio）；需要多个角色围绕一个分析案例协作时，再使用「团队协作室」；聊天更适合问答与轻操作；
6. **提问带上关键词**："最新进展 / 今天 / 实时"会触发联网搜索；"我的任务 / 我的文件"会触发平台工具查询；
7. **看到澄清卡片认真填**——AI 不猜关键参数，填得越准结果越好；
8. **长对话不慌**——上下文超限会自动压缩；复杂任务轮次不够时可按提示扩展。

### AI 使用须知

- AI 功能需要管理员预先配置模型 Provider（多模型可切换）；如果你看不到 AI 入口，可能是管理员未对你的账号开放该模块；
- AI 调用按 token 消耗折算饼干积分，长对话与大文件分析消耗更多，请留意余额；
- **AI 生成内容仅供参考**，关键分析结论与医学/遗传解读必须由研究者本人验证；
- 请勿向 AI 输入涉密、隐私或未脱敏的人类遗传资源信息；平台遵循《人类遗传资源管理条例》相关要求；
- 会话、文件、沙盒和团队协作案例按用户或授权范围隔离，但请仍遵守实验室数据分级规范；AI 生成内容和分析结论必须由研究者本人复核。

## 使用技巧与最佳实践

- **数据命名先行**：按《数据目录结构说明》组织目录与命名，能避免 80% 的流程报错；配对样本用 `样本名_1/2.fastq.gz`。
- **大文件走服务器拷贝**：浏览器上传适合中小文件；批量大数据请管理员协助直接落盘注册。
- **参数提交前截图/记录分组**：流程提交后参数即成快照，改分组需要重新提交任务。
- **先看报告再看表格**：任务成功后优先打开交互式 HTML 报告，对结果有整体印象后再下载细看。
- **善用基因 ID 转换器**：富集分析报错多半是 ID 类型不匹配，先转换再分析。
- **AI 问报错**：任务失败时，把「实时日志」的最后几十行直接贴给星尘 AI，它能帮你解读大多数常见错误。
- **及时下载重要结果**：临时性工作区文件有保留期限，重要产出请及时下载或归档。

## 常见问题与排查

### 登录后页面空白或加载失败

- 尝试强制刷新：`Ctrl + Shift + R`；
- 换一个现代浏览器（推荐 Chrome / Edge 最新版）；
- 仍不行请联系管理员确认前端服务是否正常。

### 上传文件失败

- 检查文件大小是否超过上传限制（超大文件建议服务器本地拷贝）；
- 检查网络是否稳定（分片上传中断可重试续传）；
- 确认文件格式在允许列表内（聊天附件有后缀白名单）。

### 任务提交后一直等待中

- 通常是 Worker 计算节点未就绪或排队繁忙，请联系管理员；
- 确认饼干余额充足。

### 任务运行失败

点击任务详情中的「实时日志」，重点检查：

- 输入文件路径是否正确、样本信息（分组、配对）是否完整；
- 参考基因组版本是否选对；
- 工作目录磁盘空间是否充足；
- 搞不定时：复制日志末尾发给星尘 AI，或联系管理员。

### AI 助手无法回复 / 看不到 AI 入口

- 确认管理员已为你的账号开放 AI 模块权限；
- 确认平台已配置可用的模型 Provider（管理员操作）；
- 检查饼干余额是否不足；
- 刷新页面重试；仍异常请联系管理员查看 AI 指标仪表盘与会话日志。

### 知识库文章显示不全或保存失败

- 在线编辑时文章 ID 必须唯一，不能与已有条目冲突；
- 当前实验室知识库页面只显示 `lab` 知识库中已发布、已启用的文档；其他知识库需要在「AI 配置中心 → 资源中心 → 知识库」中开启页面展示；
- 若文章已经保存但页面不可见，请让管理员检查知识库归属、`show_in_lab`、`is_enabled` 和文档发布状态，而不是先执行索引同步；
- 图片需为 png/jpg/gif/svg/webp 且单张不超过 10MB。

### 团队协作室无法使用

- 确认管理员已为账号开放对应模块权限，并确认 AgentTeams Bridge / Gateway 服务在线；
- Case 长时间没有事件时，可能是 Worker 排队、执行租约或下游 Agent 服务未就绪，请联系管理员查看案例事件流和服务日志；
- 团队协作室中的 Agent 只能使用当前 Case 授权的能力，未绑定的 Skill、MCP 或不可用工具不会被强制启用。
