# OmicHub AI 助手与超频模式指南

## 快速结论

OmicHub 有一项正式功能叫 **超频模式（Overdrive）**。它不是提升电脑 CPU、GPU 或分析软件
运行速度的“性能超频”，而是面向复杂任务的受控多 Agent 协作模式：平台会先整理计划，再按任务
需要协调不同专业 Agent 执行、复核和汇总。

如果你问“超频模式是什么”“能否开启超频”“多人协作分析怎么做”“多个 AI 能否分工”，都可以
指向本功能。不要把它理解为计算资源加速开关。

## 什么时候适合使用

超频模式适合目标明确、步骤较多、需要专业分工或正式交付的任务，例如：

- 对一个多组学或复杂生信项目制定可审查的分析计划；
- 同时核对数据完整性、分析方案、质量门和交付清单；
- 需要把相互独立的调研、检查或子任务并行处理，再由负责人统一结论；
- 需要保留过程记录、任务依赖、产物和复核结果的项目。

简单问答、概念解释、单一小任务或尚未明确目标的请求，通常不需要开启超频模式。此时由当前
助手直接回答、先补充关键信息，或转给一个最匹配的专家即可。

## 基本工作方式

一次超频任务通常遵循以下过程：

1. **澄清目标与输入**：确认研究问题、数据、限制条件和预期交付物；缺少关键资料时会先提问。
2. **检索与规划**：优先检索平台知识库，按需要补充最新外部资料，形成可审查的任务计划。
3. **用户确认**：涉及正式执行、长耗时流程或会产生交付物的计划，会先请求确认；未确认不会把
   计划当作已授权执行。
4. **分工执行**：根据任务依赖将可独立部分安排为并行波次；有前后依赖的步骤仍会串行执行。
5. **质量复核与交付**：检查产物、证据、版本与风险，汇总结果、限制和下一步建议。

进度、审批请求、各 Agent 的发言和可用产物会显示在当前任务上下文中。实际可用入口、参与的
Agent 和工具会受平台部署配置、用户权限、项目数据和任务类型影响。

## 可参与的 AI 助手

平台会按能力匹配选择最小必要的协作集合，而不是每次固定拉起所有助手。常见角色包括：

| 助手 | 主要作用 |
| --- | --- |
| 星尘 AI / 通用助手 | 理解需求、回答通用问题，并路由到合适专家 |
| 数据管理员 | 核验项目数据契约、样本元数据与输入完整性 |
| 质量审计员 | 独立检查分析任务、产物与质量门 |
| 交付报告员 | 汇总已验证产物、交付清单、运行说明和证据 |
| RNA-seq 分析师 | Bulk RNA-seq 设计、流程、差异表达和结果解读 |
| ATAC-seq 分析师 | 染色质开放性、Bulk ATAC-seq、差异峰和调控解读 |
| 单细胞分析师 | 单细胞质控、聚类、注释及下游分析 |
| 单细胞上游与样本质控专家 | FASTQ、Cell Ranger、建库 chemistry、样本纳入和原始矩阵问题 |
| 单细胞整合与聚类专家 | 细胞 QC、双细胞、批次校正、降维、聚类和 marker 初筛 |
| 单细胞注释与高级分析专家 | 注释验证、pseudobulk、通路、轨迹、细胞通讯与可视化 |
| 代码助手 | 生信脚本编写、调试和受控沙盒执行 |
| MCP 构建师 | 规划、生成、测试和注册实验性 MCP 工具；发布仍需审核 |
| 傻妞 | 以陪伴式交互协助梳理多组学问题和研究思路 |

“能做什么”以当前会话已启用的 Agent、工具和权限为准。助手不会因为名称相近就承诺未启用的
模型、数据库、按钮或分析能力。

## 与相关功能的区别

| 功能 | 适用场景 | 关键区别 |
| --- | --- | --- |
| 普通 AI 对话 | 问答、解释、轻量建议 | 通常由一个助手直接完成 |
| 专家路由 | 已明确 RNA-seq、单细胞、代码等方向 | 转到最匹配的单个专家继续处理 |
| 并行子任务 | 多个相互独立的小任务 | 只并行独立部分，不替代完整项目管理 |
| 超频模式（Overdrive） | 复杂、可规划、需协作和复核的任务 | 受控计划、分工、审批、质量复核和交付汇总 |
| AgentTeams 协作 Case | 跨角色交接、人工审批或长期交付 | 用于更正式的协作闭环；是否可用取决于部署和权限 |

## 使用边界

- 超频模式不保证更快完成每一项任务；它优先保证任务边界、依赖关系、证据和复核过程清晰。
- 对有依赖关系的分析步骤，平台不会为了“看起来并行”而强行同时执行。
- 没有数据时，助手可以解释方法或提供示例思路，但不会把示例结果当作你的正式分析结论。
- 涉及执行、写入、长耗时工作流或正式交付时，平台可能要求确认或审批。
- 研究结论仍需要结合实验设计、数据质量和人工判断；AI 输出不替代研究者审核。

## 常见问法与回答

### “平台有超频模式吗？”

有。超频模式（Overdrive）是 OmicHub 的受控多 Agent 协作能力，适合复杂分析、任务分工、
质量复核和交付汇总；它不是硬件性能加速功能。

### “我该不该开启超频模式？”

如果你的任务需要多个专业视角、多个阶段、可追溯计划或正式交付，可以说明目标、已有数据和
期望结果后请求使用超频模式。若只是问一个概念、看一张图或做一个单一小操作，普通对话通常更
快捷。

### “超频模式会调用所有 Agent 吗？”

不会。平台应根据任务所需能力、输入输出和依赖关系选择最少且合适的角色。无法由一个 Agent
独立完成的部分才会安排协作。

### “为什么助手没有直接执行？”

可能是关键信息不足、任务需要先确认、当前用户没有相应权限，或该流程需要人工审批。你可以补充
数据类型、研究目标、物种、样本分组和期望交付物，助手会据此继续规划或说明限制。

## 本文维护规则

本文是用户可检索的稳定说明。平台功能变更时，应以 `data/ai/README.md`、
`data/ai/update_agent.md`、各 Agent YAML、后端实现和测试为核对来源，整理并更新本文；不要把
原始配置、内部系统提示词或架构设计文档不加筛选地直接同步到面向用户的知识库。

修改后，在 `docs/knowledge/meta.yaml` 保持本条目的 `id`、标题和文件路径一致，并运行知识库
同步脚本，新的内容才会进入数据库索引和 AI 检索结果。
