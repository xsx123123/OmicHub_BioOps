# Docker 镜像构建国内加速 — 跨项目快速参考

> **来源**: 提炼自 `Protocol/镜像构建国内加速规范_v1.md`（IMSA v1.2）
> **用途**: 任何 Python/conda/uv 项目在国内环境做 Docker 构建时，可直接复用的加速方法集
> **日期**: 2026-08-11

---

## 0. 为什么需要这份参考

国内 Docker 构建常遇到：
- `apt-get` 卡在 400s+（境外源 `archive.ubuntu.com` / `deb.debian.org` 不稳定）
- `pip install` 超时失败（`pypi.org` / `files.pythonhosted.org` 国内慢）
- `uv sync` 看似配了镜像但还是慢（lock 文件钉死了境外 URL）
- `conda/mamba` 求解卡死（境外 conda.anaconda.org）
- PyTorch 静默拖 3GB CUDA 依赖（CPU 镜像浪费 10 分钟+）

本文档给出每个问题的**标准解法模板**，直接 COPY 到 Dockerfile 即可。

---

## 1. apt 换源（Debian / Ubuntu）

### 模板（兼容新旧版 Debian）

```dockerfile
# 放在第一个 apt-get 之前
RUN if [ -f /etc/apt/sources.list.d/debian.sources ]; then \
        sed -i 's@//deb.debian.org@//mirrors.ustc.edu.cn@g; s@//security.debian.org@//mirrors.ustc.edu.cn@g' /etc/apt/sources.list.d/debian.sources; \
    else \
        sed -i 's@//deb.debian.org@//mirrors.ustc.edu.cn@g; s@//security.debian.org@//mirrors.ustc.edu.cn@g' /etc/apt/sources.list; \
    fi
```

**要点**：
- Ubuntu 用 `archive.ubuntu.com`，Debian 用 `deb.debian.org`，按基础镜像选择
- 多阶段构建中**每个 stage 都要换**（每个 stage 是独立 rootfs）
- 防 tzdata 交互卡死：`ENV DEBIAN_FRONTEND=noninteractive TZ=Asia/Shanghai`

## 2. pip 三保险

### 模板

```dockerfile
# ① 全局配置（运行期也生效）
RUN printf '%s\n' \
      '[global]' \
      'index-url = https://pypi.mirrors.ustc.edu.cn/simple' \
      'timeout = 60' \
      'retries = 10' \
      > /etc/pip.conf

# ② 每条命令显式 -i（防基础镜像缓存 / 用户级配置覆盖）
RUN pip install --no-cache-dir -i https://pypi.mirrors.ustc.edu.cn/simple \
    some-package>=1.0
```

**要点**：
- **主源 USTC + 阿里云兜底**，不要把 `pypi.org` 放进 index 列表（pip 多源时不保证优先主源，可能挑中境外 CDN）
- 必须显式调大 `timeout`（默认 15s）和 `retries`（默认 5 次）
- `/etc/pip.conf` 对 root 和非 root 用户均生效

## 3. uv 四处独立加速点（核心）

> **uv 完全不读 `/etc/pip.conf`**，加速必须改四处，缺一不可。

### 3.1 四个卡点

| # | 卡点 | 解法 |
|---|---|---|
| ① | uv 自身安装来源 | 从 PyPI 装，**不要从 GHCR**（国内常被墙） |
| ② | 项目级默认 index | `pyproject.toml` 配 `[[tool.uv.index]]` |
| ③ | Dockerfile 构建期 | ENV + 每条命令 `--index-url` 双保险 |
| ④ | uv.lock 钉死 URL | 用国内源重新 `uv lock` |

### 3.2 完整模板

**pyproject.toml**（② 项目级默认）：

```toml
[[tool.uv.index]]
name = "ustc"
url = "https://pypi.mirrors.ustc.edu.cn/simple/"
default = true

[[tool.uv.index]]
name = "aliyun"
url = "https://mirrors.aliyun.com/pypi/simple/"
```

**Dockerfile**（① ③ 构建期）：

```dockerfile
# ① 从 PyPI 装 uv（不从 GHCR）
RUN pip install --no-cache-dir -i https://pypi.mirrors.ustc.edu.cn/simple \
    "uv==0.6.14"

# ③ ENV + 每条命令 --index-url
ENV UV_INDEX_URL=https://pypi.mirrors.ustc.edu.cn/simple \
    UV_EXTRA_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ \
    UV_HTTP_TIMEOUT=120 \
    UV_HTTP_RETRIES=5 \
    UV_LINK_MODE=copy

# 每条 uv sync / uv pip install 都显式带 --index-url
RUN --mount=type=cache,target=/root/.cache/uv,sharing=locked \
    uv sync --frozen --no-dev \
    --index-url https://pypi.mirrors.ustc.edu.cn/simple/

RUN uv pip install --no-cache \
    --index-url https://pypi.mirrors.ustc.edu.cn/simple/ \
    "some-package>=1.0"
```

**uv.lock 国内化**（④）：

```bash
# pyproject.toml 已配 [[tool.uv.index]] 时，直接 uv lock
uv lock

# 未配置时，临时指定
UV_INDEX_URL=https://pypi.mirrors.ustc.edu.cn/simple uv lock

# 验证：应输出 0
grep -c "files.pythonhosted.org" uv.lock
```

### 3.3 常见陷阱

- **`uv sync --frozen` 直接用 lock 文件里的 URL 下载**，ENV 和 `--index-url` 参数救不了。必须在境外网络 `uv lock` 后重跑一次国内源 lock
- **`UV_LINK_MODE=copy`**：Docker BuildKit cache mount 和容器目录在不同文件系统时，hardlink 失败会打 warning，设 copy 消除
- **`sharing=locked`**：多并发构建时防止 cache 损坏

## 4. conda / mamba 换源

### 模板

```dockerfile
# 注意：写到 $HOME 下，不是 /root（micromamba 按 HOME 环境变量找配置）
RUN printf '%s\n' \
      'show_channel_urls: true' \
      'default_channels:' \
      '  - https://mirrors.ustc.edu.cn/anaconda/pkgs/main' \
      '  - https://mirrors.ustc.edu.cn/anaconda/pkgs/free' \
      '  - https://mirrors.ustc.edu.cn/anaconda/pkgs/r' \
      '  - https://mirrors.ustc.edu.cn/anaconda/pkgs/msys2' \
      'custom_channels:' \
      '  conda-forge: https://mirrors.ustc.edu.cn/anaconda/cloud' \
      '  bioconda: https://mirrors.ustc.edu.cn/anaconda/cloud' \
      '  menpo: https://mirrors.ustc.edu.cn/anaconda/cloud' \
      '  pytorch: https://mirrors.ustc.edu.cn/anaconda/cloud' \
      'channel_priority: flexible' \
      'channels:' \
      '  - conda-forge' \
      '  - bioconda' \
      '  - menpo' \
      '  - defaults' \
      > /root/.condarc
```

**要点**：
- **`custom_channels` 的值是频道基地址**：必须写到 `.../anaconda/cloud`；Conda 会自动追加 `conda-forge`、`bioconda` 等键名。把频道名写进值会形成 `.../conda-forge/conda-forge/...` 并导致 404。
- **`custom_channels` 必须含 bioconda**（否则 `-c bioconda` 仍走境外）
- **`channel_priority: flexible`**（strict 多渠道混装容易无解）
- **`.condarc` 必须写到 `$HOME`**（基础镜像设了 `ENV HOME=/home/xxx` 时，写 `/root` 被静默忽略）
- micromamba 镜像写 `/home/$MAMBA_USER/.condarc`

## 5. 大件依赖防护

### 5.1 GPU 包前置（PyTorch 3GB 问题）

CPU 镜像装含 `torch` 依赖的包（`scvi-tools`、`torch-geometric`、`transformers` 等）前，**先 conda 装 CPU-only PyTorch**：

```dockerfile
# 先装 CPU-only PyTorch（~272MB，PyPI GPU 路线 ~3GB）
RUN mamba install -y -c pytorch -c conda-forge \
        pytorch=2.4 \
        cpuonly \
    && mamba clean --all -y

# 再装上层包（不再拉 CUDA 依赖）
RUN pip install --no-cache-dir "scvi-tools>=1.1.0"
```

**判断标准**（满足任意一条即应前置）：
- `pip install --dry-run <pkg> 2>&1 | grep -i torch` 有输出
- 镜像无 NVIDIA GPU / 不挂 `--gpus`
- 同类：`tensorflow` → `tensorflow-cpu`、`jax` → `jax[cpu]`

### 5.2 境外大件 vendor 化

GitHub Release / S3 等 >10MB 制品，预下载到构建上下文的 `vendor/`：

```dockerfile
# 原始下载命令（注释保留，方便升级版本）
# curl -L -o vendor/gatk-4.5.0.zip \
#   "https://github.com/broadinstitute/gatk/releases/download/4.5.0.0/gatk-4.5.0.0.zip"
COPY vendor/gatk-4.5.0.zip /tmp/
RUN unzip -q /tmp/gatk-4.5.0.zip -d /opt && rm /tmp/gatk-4.5.0.zip
```

**要点**：
- `vendor/` 加入 `.gitignore`（二进制不入库）
- 用 `ARG` 贯通版本号，升级只改 ARG + 换 vendor 文件
- 预下载在宿主机执行（支持断点续传 `curl -C -`）

## 6. npm / Node 换源（前端构建镜像）

```dockerfile
# npm
RUN npm config set registry https://registry.npmmirror.com

# pnpm
RUN pnpm config set registry https://registry.npmmirror.com

# yarn
RUN yarn config set registry https://registry.npmmirror.com
```

或在命令中直接指定：

```dockerfile
RUN npm install --registry https://registry.npmmirror.com
```

## 8. 通用避坑清单

| 坑 | 现象 | 解法 |
|---|---|---|
| tzdata 交互卡死 | apt install 卡在选时区 400s+ | `ENV DEBIAN_FRONTEND=noninteractive TZ=Asia/Shanghai` |
| 多阶段忘换源 | 第二个 stage 下载极慢 | 每个 stage 独立 rootfs，**每个 stage 都要换** |
| conda strict 无解 | `PackagesNotFoundError` 或求解无限等待 | `channel_priority: flexible` |
| R + Python 混装 icu 冲突 | `r-base` 安装报 icu 版本冲突 | `r-base` 钉 conda-forge 最新 minor |
| ORM 声明 JSONB 实际是 json | `operator does not exist: json ?` | `?` 换 `->>'key' IS NOT NULL` |
| uv.lock 有 pythonhosted.org | `uv sync --frozen` 仍走境外下载 | 重新 `uv lock` 用国内源 |
| BuildKit cache hardlink 警告 | `Failed to hardlink; falling back to copy` | `ENV UV_LINK_MODE=copy` |
| GHCR 拉镜像超时 | `COPY --from=ghcr.io/...` 卡住 | 改从 PyPI / apt / npm 安装 |

## 9. 新项目接入 Checklist

```markdown
- [ ] apt/alpine 换源层在每个 stage 第一道
- [ ] `ENV DEBIAN_FRONTEND=noninteractive`（如适用）
- [ ] pip: `/etc/pip.conf` + 每条命令 `-i USTC`
- [ ] uv: pyproject.toml `[[tool.uv.index]]` + 每条命令 `--index-url` + uv.lock 国内化
- [ ] conda: `.condarc` 写到 `$HOME`，`custom_channels` 含 bioconda
- [ ] 含 torch 的 CPU 镜像 → GPU 前置
- [ ] GitHub/S3 大件 → vendor 化
- [ ] npm/pnpm → `registry.npmmirror.com`
- [ ] Alpine → `mirrors.ustc.edu.cn`
```

## 10. 镜像源测速（验证当前网络到哪个源最快）

```bash
# 在构建机器上跑
for mirror in \
    "https://pypi.mirrors.ustc.edu.cn/simple/" \
    "https://mirrors.aliyun.com/pypi/simple/" \
    "https://mirrors.huaweicloud.com/repository/pypi/" \
    "https://pypi.org/simple/"; do
    printf "%-50s " "$mirror"
    curl -o /dev/null -s -w "DNS: %{time_namelookup}s  Connect: %{time_connect}s  Total: %{time_total}s  Speed: %{speed_download} B/s\n" \
        --max-time 10 "$mirror"
done
```

选 Total 最短的作为主源。
