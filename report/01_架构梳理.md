# 01 · 架构梳理

## 1. 项目定位

- **名称**：OmicHub（星尘工作站）
- **出品**：华中农业大学园艺林学学院基因组学实验室
- **定位**：私有化多组学分析平台，让组内成员通过 Web 界面完成 RNA-seq / ATAC-seq 等分析任务的全生命周期管理，告别命令行提交。
- **维护规模**：单人全栈开发（这是理解其技术债务分布的关键背景）
- **当前版本**：0.1.0（master 分支，最近提交 2026-07-05）

### 3.1 请求处理链路

```
Browser → Nginx → FastAPI
  → RateLimitMiddleware (最外层, Redis 不可用降级放行)
  → AuditMiddleware (记录写操作, 依赖 Auth 注入的 user_id)
  → CookieRequiredMiddleware (消费类路由的账户守卫)
  → AuthMiddleware (JWT 解析, 公开路径在 PUBLIC_PATHS 配置)
  → CORSMiddleware
  → APIRouter (/api/v1 前缀)
  → 路由依赖注入 (Depends → 当前用户/DB session/管理员守卫)
  → Application Service (用例编排 + 事务)
  → Domain Service / Repository (业务规则)
  → Infrastructure (SQLAlchemy ORM → PostgreSQL)
```

### 3.2 异常处理三级兜底

`main.py:222-250` 注册了三级异常处理器：
1. `OmicHubError` → 业务异常，返回对应 status_code + detail
2. `RequestValidationError` → 422 + 具体字段错误（避免被 500 吞掉）
3. `Exception` → 兜底 500「系统内部错误，请联系管理员」+ 完整堆栈入日志

### 4.1 路由守卫逻辑

`router/index.ts:226-267` 实现三层守卫：
1. **首次部署检测**：`checkSetupRequired()` 检测系统是否已有 admin，无则强制跳转 `/setup`
2. **登录态校验**：`requiresAuth` 路由未登录跳 `/login?redirect=`
3. **已登录访问登录页**：跳回首页

## 5. 核心模块数据流

### 5.1 流程分析任务链路（核心业务）

```
用户提交 → POST /api/v1/tasks/submit
  → TaskService.submit()
  → GenericFlowBuilder 读取 flows/{flow_id}.yaml 的 pipeline_mapping
  → 生成 config.yaml + samples.csv + contrasts.csv 到 {storage}/users/{uid}/results/{task_id}/
  → TaskDomainService 创建任务记录（状态 PENDING）
  → Celery delay → run_snakemake task（队列 analysis）
  → Worker: LocalSnakemakeExecutor subprocess 调用 snakemake CLI
  → 实时日志通过 Redis Pub/Sub → publish_task_log
  → 前端 WebSocket/SSE 订阅任务频道，滚动显示日志
  → 完成后结果落盘 {storage}/users/{uid}/results/{task_id}/
  → FileService 扫描入库 → 任务详情页可下载
```

**流程扩展机制**：新增流程只需在 `flows/` 添加 YAML，无需改后端代码。`pipeline_mapping` 节点声明参数到配置文件的映射，支持点号嵌套、计算字段、样本表/比较组生成。

### 5.2 AI 助手 Agent 调度闭环（生产主力）

```
前端 AgentSandbox 发消息 (agent_id)
  → useAgentChatStream: fetch + ReadableStream 解析 SSE
  → POST /api/v1/chat/stream {agent_id, session_id, messages}
  → ChatService.stream_agent_chat()
    → AgentService.assemble_context(agent_id)
      → 查 agent_templates 表拿 system_prompt + model_id + mcp_ids + skill_ids
      → _resolve_model: agent.model_id → ai_provider_configs 解析真实连接信息
      → SqlAlchemyMCPServerRepository.get_by_ids 拉绑定的 MCP server
      → MCP 工具 inputSchema → OpenAI tools 格式转换
      → system_prompt += SkillService.build_skills_prompt(skill_ids)
      → 返回 AgentContext{agent, model_config, system_prompt, tools, mcp_servers}
    → 落库用户消息(sanitize_text 脱敏) + AI 占位消息(status=streaming)
    → Agentic 循环（上限 8 轮）:
      → ProviderManager.chat_stream(tools=...)
      → 累积 text 逐 chunk yield（打字机）
      → 收到 tool_calls:
        → yield tool_call SSE
        → 在 mcp_servers 里按 tool_name 找 server
        → MCPClient.call_tool 执行
        → yield tool_result SSE（含 success/结果）
        → append assistant tool_calls + role:tool 结果消息
        → continue 下一轮
      → 无 tool_calls: 落库完整 content + yield done
    → 异常/超轮次落库已生成内容 + yield error
```

**两代 AI 架构并存**：
- Legacy（WebSocket）：`/api/v1/ai/ws` + `ai_service.py` + `useAIWebSocket.ts` + `AIChat.vue` — 保留但非主力
- Current（SSE Agent）：`/api/v1/chat/stream` + `chat_service.py` + `useAgentChatStream.ts` + `AgentWorkspace.vue` — 生产主力

### 5.3 数据管理多租户隔离

```
路径规范化: {storage_path}/users/{user_id}/raw/  与  /results/
FileService 路径工厂: user_raw_dir / user_results_dir
Repository 层所有方法首参 user_id + WHERE 过滤（杜绝水平越权）
get_by_id 同时校验归属（越权返 404）

大文件上传:
  init_upload (配额预检→403, 秒传 MD5, 断点续传)
  → save_chunk (MD5 校验 + 幂等, 5MiB 切片, 3 路并发)
  → merge_upload (合并 + 总 MD5 + 原子累加配额 + 清理临时分片)

生命周期（Celery Beat）:
  reconcile_used_storage (每日 3:00 盘点物理目录校正 used_storage)
  cleanup_expired (僵尸会话/30天临时/90天冷数据归档或删除)
```

### 5.4 饼干积分系统

内置虚拟货币，消费类路由经 `CookieRequiredMiddleware` 拦截：
- 账户表 + 交易流水表（CHECK 约束：adjust 可正负，earn/refund/unfreeze>=0，spend/freeze<=0）
- 定价表（per_run / per_sample / per_comparison 三种计费单位）
- Admin 可调账、查看流水审计
- Cookie WebSocket 实时推送余额变动

## 6. 部署架构（双栈解耦）

```
主栈 docker-compose.yml:
  nginx (:8888) → web (:8000) + beat + flower (:5555) + db (:5432) + cache (:6379)
  web 挂载 src/flows/docs/data/alembic 为 ro（热重载）
  web entrypoint 先跑 alembic upgrade head 再启动 uvicorn --workers 2

Worker 栈 docker-compose.worker.yml:
  仅 worker，挂载宿主 conda 与流程代码
  通过外部网络 omichub_net 与主栈共享 Redis + DB
  通过宿主 /data/omichub 共享任务数据

生产 override docker-compose.prod.yml:
  4 uvicorn worker + 不暴露 DB 端口 + SSL
```

**关键设计**：Web 控制面与 Celery Worker 计算面逻辑解耦，Worker 可 `--scale` 水平扩展，适合把计算节点部署到有 GPU/大内存的机器。
