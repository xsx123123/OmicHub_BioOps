# 02 · 使用方法

## 1. 环境要求

- Python >= 3.11（用 uv 管理依赖）
- Node.js >= 18
- Docker >= 24.0 + Docker Compose v2
- uv（Python 包管理器）

## 2. 本地开发

```bash
# 1. 检查环境变量（.env 已存在，按需编辑 JWT_SECRET_KEY / AL_API_KEY 等）
vim .env

# 2. 安装后端依赖
uv sync

# 3. 安装前端依赖
cd frontend && npm install && cd ..

# 4. 启动 PostgreSQL + Redis（Docker）
make docker-up

# 5. 执行数据库迁移
make migrate

# 6. 初始化管理员账号（二选一）
make init-admin                    # 命令行
# 或浏览器访问 http://localhost:5173/setup 网页注册（仅系统无 admin 时可用）

# 7. 初始化饼干定价策略（可选）
make init-cookies

# 8. 启动后端开发服务器
make dev                           # uvicorn --reload :8000

# 9. 启动前端开发服务器（另一个终端）
make frontend-dev                  # vite :5173
```

访问：前端 http://localhost:5173，API 文档 http://localhost:8000/docs

## 3. Docker 部署（推荐）

### 3.1 首次部署

```bash
# 0. 宿主目录前置（首次需 sudo；web 与 worker 共享任务数据目录）
sudo mkdir -p /data/omichub
sudo chown $USER:$USER /data/omichub

# 1. 检查 .env，必须修改：
#    JWT_SECRET_KEY（随机长字符串）
#    AL_API_KEY（阿里云 DashScope API Key）
#    OMICHBUB_INIT_ADMIN_PASSWORD（生产必填）
#    AI_CONFIG_ENCRYPTION_KEY（固定值，加密 API Key，首次部署后不可更改）

# 2. 构建前端
cd frontend && npm install && npm run build && cd ..

# 3. 启动主栈（自动创建跨栈网络 omichub_net）
make docker-up

# 4. 启动独立 Worker 栈（计算节点）
make docker-up-worker

# 5. 执行数据库迁移
docker exec omichub-web uv run alembic upgrade head

# 6. 初始化管理员（推荐浏览器访问 :8888/setup）
docker exec omichub-web uv run python scripts/init_admin.py

# 7. 初始化饼干定价（可选）
docker exec omichub-web uv run python scripts/init_cookies.py

# 8. 访问 http://localhost:8888
```

### 3.2 一键拉起

```bash
make docker-up-all                 # 主栈 + Worker（含前端构建）
```

### 3.3 生产环境

```bash
# 主栈：生产 override（4 uvicorn worker + 不暴露 DB + SSL）
docker compose -f deploy/docker/docker-compose.yml \
               -f deploy/docker/docker-compose.prod.yml up -d

# Worker 栈：水平扩展
docker compose -f deploy/docker/docker-compose.worker.yml --scale worker=2 up -d
```

生产注意事项：
- `APP_ENV=production`、`APP_DEBUG=false`
- `OMICHBUB_INIT_ADMIN_PASSWORD` 强密码
- `AI_CONFIG_ENCRYPTION_KEY` 固定值（首次部署后不可更改，否则已加密 API Key 无法解密）
- 配置 SSL 证书挂载到 nginx
- 不暴露数据库端口（prod.yml 已禁用）

## 4. 代码更新后如何更新容器

| 改动类型 | 推荐命令 | 说明 |
|---|---|---|
| 只改前端（`frontend/src/`） | `make docker-reload` | 重建 dist + 重启 nginx/web |
| 只改后端 Python（`src/`） | `docker restart omichub-web omichub-beat omichub-worker` | 容器挂载 `src:ro`，重启即加载 |
| 改流程 YAML（`flows/*.yaml`） | `curl -X POST http://localhost:8000/api/v1/flows/reload` | 热重载，无需重启 |
| 改数据库模型/新增迁移 | 先 `make check-migrations`，再 `make docker-reload` | entrypoint 自动跑 alembic upgrade head |
| 改依赖（`pyproject.toml`/Dockerfile） | `make docker-start` | 必须重建镜像（会清空数据卷） |
| 彻底从零重建 | `make docker-start` | purge + build --no-cache + 构建前端 + up |

> ⚠️ **改前端后必须重启 nginx**：Vite 构建会清空重建 dist（新 inode），旧 nginx 进程持有旧目录句柄导致页面不更新。用 `make docker-reload` 或 `docker restart omichub-nginx`。

## 5. 流程（Flow）扩展机制

OmicHub 采用 **YAML 声明式 + 通用构建器** 架构，新增流程通常只需在 `flows/` 加 YAML，无需改后端。

### 5.1 新增流程步骤（以 chip_seq 为例）

1. **创建 `flows/chip_seq.yaml`**，包含：
   - `meta`：流程元信息（`id` 必须全局唯一且符合 `^[a-z][a-z0-9_]*$`）
   - `parameters`：前端动态表单参数定义
   - `execution`：Snakefile 路径、资源配置、主配置文件名
   - `sample_sheet`：样本表校验规则
   - `pipeline_mapping`：参数到配置文件的映射规则

2. **编写 `pipeline_mapping`**：

```yaml
pipeline_mapping:
  config_fields:           # 直接写入主配置文件的字段（支持点号嵌套）
    - project_name
    - peak_calling.macs2_qvalue
  computed_fields:         # 由构建器动态注入的字段
    workflow: "__work_dir__"
    sample_csv: "__samples_csv__"
    paired_csv: "__contrasts_csv__"
  sample_sheet:
    output_name: "samples.csv"
    columns: { sample: sample, group: group }
  comparisons:
    output_name: "contrasts.csv"
    columns: { Control: Control, Treat: Treat }
```

3. **放置 Snakefile**：确保 `execution.snakefile` 指向的文件存在并能读取生成的配置。

4. **热重载**：`curl -X POST http://localhost:8000/api/v1/flows/reload -H "Authorization: Bearer <token>"`

5. **前端使用**：`/api/v1/flows/chip_seq/schema` 获取参数 JSON Schema 渲染表单；提交任务 `flow_id=chip_seq`。

### 5.2 已有流程

- `flows/rna_seq.yaml`（342 行）— RNAFlow，主配置 `config.yaml`
- `flows/atac_seq.yaml`（328 行）— ATACFlow，主配置 `analysis.yaml`

## 6. AI Provider 配置

支持两种方式（可共存，方式 1 优先）：

### 方式 1（推荐）：外置 YAML

编辑 `data/ai_providers.yaml`，支持 `${ENV_VAR}` 插值引用 `.env` 密钥：

```yaml
providers:
  - name: aliyun
    provider_type: openai_compatible
    model: qwen3.7-max
    base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
    api_key: ${AL_API_KEY}
    is_default: true
```

### 方式 2：环境变量兜底

仅在数据库无 Provider 时生效，`.env` 设置 `KIMI_API_KEY` / `OPENAI_API_KEY`。

### AI 助手配置

每个助手一个 YAML（`data/ai/{name}.yaml`），`data/OmicHub.yaml` 的 `agents.enabled` 列表控制加载哪些：

```yaml
# data/OmicHub.yaml
agents:
  enabled:
    - general    # data/ai/general.yaml
    - rnaseq     # data/ai/rnaseq.yaml
    - code
    - viz
```

## 7. 数据下载（EBIDownload）

内置 Rust 写的 EBIDownload 工具从 EBI/NCBI 下载 FASTQ，下载完成自动出现在「数据管理」中。

```bash
# 1. 构建 Rust 二进制
cd pipelines/EBIDownload
CC=clang cargo build -p ebidownload-cli --release

# 2. 装运行时依赖 sra-tools
mamba install -n base -c bioconda sra-tools

# 3. 放到 /data/omichub/bin/
mkdir -p /data/omichub/bin
cp target/release/EBIDownload /data/omichub/bin/EBIDownload
cp EBIDownload.yaml /data/omichub/bin/EBIDownload.yaml

# 4. .env 开启
ENABLE_EBI_DOWNLOAD=true
```

## 8. 实验室知识库

文档以纯文件存于 `docs/knowledge/`：
- `meta.yaml` — 导航配置（标题、文档列表、可选 category 分类）
- `*.md` — Markdown 正文

服务每次读盘，保存后无需重启即生效。管理员可在 `/knowledge` 页在线编辑（md-editor-v3），保存接口带路径遍历防护 + 原子写（先 `.tmp` 再 `replace`）。

| 命令 | 说明 |
|------|------|
| `make dev` | 启动后端开发服务器 |
| `make frontend-dev` | 启动前端开发服务器 |

| `make clean` | 清理 Python 缓存 |
