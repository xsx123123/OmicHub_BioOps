# 07 · K8s 大规模部署方案（最简路径）

> 目标：从当前 Docker Compose 平滑迁移到 K8s，支撑万人级并发
> 原则：最小改动、渐进式、先跑通再优化

## 一、为什么选 K8s

| 维度 | Docker Compose | K8s |
|------|---------------|-----|
| 水平扩展 | 手动 `--scale` | HPA 自动伸缩 |
| 自愈 | restart:unless-stopped | Pod 重启 + 健康探针 |
| 滚动更新 | 需停机 | 零停机滚动 |
| 资源调度 | 固定宿主 | 跨节点自动调度 |
| 配置/密钥 | .env 文件 | ConfigMap + Secret + KMS |
| 存储 | bind mount | PVC + StorageClass |
| 多租户 | 无 | Namespace + NetworkPolicy + Quota |

## 二、最简迁移路径（5 步走）

### 步骤 1：镜像准备（1 天）

当前 Dockerfile 已可用，仅需微调：

```dockerfile
# Dockerfile.prod — 生产镜像
FROM python:3.11-slim AS builder
COPY --from=ghcr.io/astral-sh/uv:0.5.11 /uv /usr/local/bin/uv  # 锁定版本
WORKDIR /app
COPY pyproject.toml uv.lock* ./
RUN uv sync --frozen --no-dev --no-install-project
COPY src/ ./src/
COPY alembic.ini alembic/ ./
RUN uv sync --frozen --no-dev

FROM python:3.11-slim AS runtime
RUN apt-get update && apt-get install -y --no-install-recommends curl && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=builder /app/.venv /app/.venv
COPY --from=builder /app/src /app/src
COPY --from=builder /app/alembic.ini /app/alembic.ini
COPY --from=builder /app/alembic /app/alembic
ENV PATH="/app/.venv/bin:$PATH"
EXPOSE 8000
CMD ["uvicorn", "omichub.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**关键改动**：不装 snakemake（web 不需要）、uv 版本锁定、去掉 :latest tag。

### 步骤 3：核心 manifests（3 天）

#### 3.1 Web Deployment + HPA

```yaml
# web-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: omichub-web
spec:
  replicas: 3
  selector:
    matchLabels: {app: omichub, component: web}
  template:
    metadata:
      labels: {app: omichub, component: web}
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
        fsGroup: 1000
      containers:
      - name: web
        image: registry.example.com/omichub-web:v1.0.0
        ports: [{containerPort: 8000}]
        envFrom:
        - configMapRef: {name: omichub-config}
        - secretRef: {name: omichub-secret}
        resources:
          requests: {cpu: 500m, memory: 1Gi}
          limits: {cpu: 2000m, memory: 4Gi}
        readinessProbe:
          httpGet: {path: /health, port: 8000}
          initialDelaySeconds: 10
        livenessProbe:
          httpGet: {path: /health, port: 8000}
          initialDelaySeconds: 30
        volumeMounts:
        - name: storage
          mountPath: /data/omichub
      volumes:
      - name: storage
        persistentVolumeClaim: {claimName: omichub-data}
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: omichub-web-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: omichub-web
  minReplicas: 3
  maxReplicas: 20
  metrics:
  - type: Resource
    resource: {name: cpu, target: {type: Utilization, averageUtilization: 70}}
```

#### 3.2 Worker Deployment（计算节点，可独立扩展）

```yaml
# worker-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: omichub-worker
spec:
  replicas: 2  # 按队列负载 HPA 扩缩
  selector:
    matchLabels: {app: omichub, component: worker}
  template:
    metadata:
      labels: {app: omichub, component: worker}
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
      containers:
      - name: worker
        image: registry.example.com/omichub-worker:v1.0.0  # 含 snakemake
        command: ["celery", "-A", "omichub.infrastructure.celery_app.celery",
                  "worker", "-Q", "analysis", "--loglevel=info",
                  "--concurrency=4"]
        envFrom:
        - configMapRef: {name: omichub-config}
        - secretRef: {name: omichub-secret}
        resources:
          requests: {cpu: 2000m, memory: 8Gi}
          limits: {cpu: 8000m, memory: 32Gi}
        volumeMounts:
        - name: storage
          mountPath: /data/omichub
        - name: conda-envs
          mountPath: /data/omichub/.conda_envs
      volumes:
      - name: storage
        persistentVolumeClaim: {claimName: omichub-data}
      - name: conda-envs
        persistentVolumeClaim: {claimName: omichub-conda}
```

#### 3.3 Ingress + cert-manager（替代 nginx 容器）

```yaml
# ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: omichub-ingress
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
    nginx.ingress.kubernetes.io/proxy-body-size: 64m
    nginx.ingress.kubernetes.io/proxy-read-timeout: "86400"
    nginx.ingress.kubernetes.io/limit-rps: "50"
spec:
  tls:
  - hosts: [omichub.example.com]
    secretName: omichub-tls
  rules:
  - host: omichub.example.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service: {name: omichub-web, port: {number: 8000}}
      - path: /
        pathType: Prefix
        backend:
          service: {name: omichub-frontend, port: {number: 80}}
```

#### 3.4 NetworkPolicy（网络隔离）

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: omichub-default-deny
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: web-allow-ingress
spec:
  podSelector: {matchLabels: {component: web}}
  ingress:
  - from: [{namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: ingress-nginx}}}]
  egress:
  - to: [{podSelector: {matchLabels: {component: db}}}]
  - to: [{podSelector: {matchLabels: {component: redis}}}]
  - to: [{namespaceSelector: {}}]  # 允许出站到外网（AI API）
```

## 三、托管服务优先策略（最省心）

万人级**强烈建议用云托管服务**，不自管有状态组件：

| 组件 | 自管方案 | 云托管方案（推荐） | 理由 |
|------|---------|-------------------|------|
| PostgreSQL | StatefulSet + CloudNativePG | 阿里云 RDS / AWS RDS | 主从/备份/PITR/监控开箱即用 |
| Redis | StatefulSet | 阿里云 Redis / AWS ElastiCache | 哨兵/集群/持久化托管 |
| 对象存储 | MinIO Operator | 阿里云 OSS / AWS S3 | 11 个 9 持久性、低成本 |
| 容器镜像库 | Harbor | 阿里云 ACR / AWS ECR | 漏洞扫描、签名、全球加速 |
| 负载均衡 | Ingress NGINX | 云 SLB + Ingress | 四层+七层、SSL 卸载 |
| 监控 | Prometheus Operator | 云监控 / Grafana Cloud | 托管告警、长存储 |

## 四、Helm 一键部署

```bash

helm install omichub deploy/k8s/omichub -f values.yaml

  --set image.tag=v1.0.0 \
  --set externalDatabase.host=$RDS_HOST \
  --set externalDatabase.password=$RDS_PWD \
  --set externalRedis.host=$REDIS_HOST \
  --set objectStorage.bucket=$OSS_BUCKET
```

## 五、渐进式迁移路线

| 阶段 | 时间 | 目标 | 步骤 |
|------|------|------|------|
| 1 | 1 周 | 镜像 + Helm 骨架 | Dockerfile 优化、Chart 编写、本地 kind 验证 |
| 2 | 1 周 | 无状态服务上 K8s | web/flower 上 K8s，DB/Redis 仍用旧 Docker 或云托管 |
| 3 | 1 周 | 有状态服务托管 | PG→RDS、Redis→云 Redis、存储→NAS+OSS |
| 4 | 1 周 | Worker 上 K8s | 计算 Pod 化、流程容器化、多队列 |
| 5 | 持续 | 可观测+安全加固 | Prometheus、NetworkPolicy、Falco、Kyverno |
